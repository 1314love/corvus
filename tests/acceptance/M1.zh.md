# Corvus M1 验收手册

状态：M1 里程碑的可执行验收手册。读者：从未接触本仓库的 QA 操作员。主路径通过 MCP 端点驱动真实浏览器，并为四个 M1 工具记录证据。请按顺序执行。

## 1. 范围

M1 只证明一条真实的端到端链路：

```
MCP 客户端  ->  corvusd  ->  扩展  ->  Chromium  ->  网页
            <-           <-        <-            <-
```

本次只验收四个已冻结的 M1 工具：

| 工具 | 用途 |
|---|---|
| `browser_navigate` | 加载 http/https/file URL 并等待新文档，返回 `loaded` 和最终 `url` |
| `page_snapshot` | 导出紧凑 DOM + 可访问性树，并生成 `@eN` 引用 |
| `browser_click` | 用完整的指针/鼠标事件序列点击 `@eN` 或 CSS 选择器 |
| `browser_type` | 用原生 setter 和输入事件向文本框或 contenteditable 输入 |

M1 的参数形状已经冻结：`browser_navigate {url, tab_id?}`、
`page_snapshot {tab_id?, mode?: "interactive" | "full"（默认 "interactive"）、
max_nodes?: 40..3000}`、`browser_click {target, tab_id?}`、
`browser_type {target, text, clear?（默认 true）、blur?、tab_id?}`。
`target` 是快照引用（如 `@e12`）或 CSS 选择器。

需求文档中的其他能力不属于本次验收范围。

## 2. 所需环境

- Windows 10 或更高版本。命令以 MSYS bash 编写；macOS/Linux 换成对应二进制路径即可。
- Rust 1.82 或更高版本和 Cargo。参考机器上 Cargo 位于
  `C:/Users/Administrator/.cargo/bin/cargo.exe`，不在 `PATH` 中；请使用绝对路径或加入 `PATH`。
- `curl` 和 `bash`。本地验收页服务器使用 `node`；`node` 仅用于格式化 JSON 时是可选的。
- 基于 Chromium 的浏览器。参考环境是微软 Edge 157。Chrome 或 Chromium 120+ 也可以，
  但加载方式不同：微软 Edge 会忽略命令行 `--load-extension`，必须通过
  `edge://extensions` 加载目录；需要脚本化启动时请使用 Chrome 或 Chromium。
- 正常的桌面会话，浏览器窗口必须可见。不要在锁屏或断开远程桌面时执行：点击依赖元素命中测试。
- 不需要联网。验收页是本地固定页面。

## 3. 构建并启动守护进程

在仓库根目录执行：

```bash
cargo build --offline -p corvusd
```

如果机器可以访问软件源，可去掉 `--offline`。启动：

```bash
./target/debug/corvusd.exe serve
```

（macOS/Linux：`./target/debug/corvusd serve`。）

stderr 上应出现：

```
websocket transport listening addr=127.0.0.1:7330
mcp http listening url=http://127.0.0.1:7331/mcp
```

在第二个终端检查健康状态：

```bash
mkdir -p tests/report/evidence/$(date +%F)
EVID=tests/report/evidence/$(date +%F)
curl -s http://127.0.0.1:7331/health | tee "$EVID/health-before.json"
```

期望包含 `version`、`protocol` = `2025-06-18`、`ws_addr` =
`127.0.0.1:7330`、`http_addr` = `127.0.0.1:7331`，第 4 节完成前
`browsers` 为 `[]`。把这份 JSON 作为证据保存。

保持守护进程运行。如果端口已被占用，先停掉另一个守护进程，不要启动第二个；或者显式用
备用端口启动（`serve --ws-port 17330 --http-port 17331`），并在下文使用对应端口。

## 4. 在 Edge 中以未打包方式加载扩展

1. 在浏览器中打开 `edge://extensions`。
2. 打开**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择本仓库的 `extension/` 目录（包含
   `manifest.json` 的那一层）。
4. 确认出现 Corvus 卡片且没有错误。记下卡片上的扩展 ID。参考环境的未打包路径生成了
   `pdgemoghkehbjpklbmkmchgfmpfghbl`；路径不同时 ID 通常不同，请记录实际值。
5. 打开 Service Worker 控制台（`Inspect views: service worker`），确认有
   hello / hello_ack 日志，且没有未捕获异常。打开工具栏弹窗，状态点必须显示已连接。
   不要打开 debugger 开关：M1 使用 DOM 通道。
6. 重新执行健康检查：
   `curl -s http://127.0.0.1:7331/health | tee "$EVID/health-after.json"`。
   `browsers` 中必须出现一条记录，包含 `id`、`profile`、
   `extension_version`、`capabilities`、`connected_at_ms`。参考运行的
   id 是 `edge:33628f01180d3d48`，capabilities 是
   `["dom","scripting"]`。capabilities 必须包含 `dom`。

如果 `browsers` 一直为空，说明扩展没有完成 hello 握手。如果存在浏览器记录但没有
`dom`，立即停止，并记录 hello 与 hello_ack 的原始帧：此时所有 M1 工具都会返回
`CAPABILITY_UNAVAILABLE`。

记录：浏览器名称与版本、扩展 ID、`/health` 返回的 `browsers` 数组、扩展页截图。

## 5. 提供本地验收页

在第三个终端启动固定页面服务器：

```bash
node tests/acceptance/fixtures/serve.mjs
```

期望输出：`serving http://127.0.0.1:8808/`。在测试浏览器中打开一次
`http://127.0.0.1:8808/`，确认页面正常显示。固定页面包含：

| 元素 | 用途 |
|---|---|
| `h1#h` "Corvus E2E" | 页面标识 |
| `input#q`，占位符 "type here" | `browser_type` 的目标 |
| `button#go` "Run" | `browser_click` 的目标；把 `clicked:<value>` 写入 `p#out` |
| `p#out`，初始为 "idle" | 点击携带输入值的可见证据 |
| `a#lnk` "Jump" 和 `p#sec` | 额外可交互内容和同页链接 |

参考运行的交互快照返回 7 个节点，`@e1` 对应 `input#q`，`@e2` 对应
`button#go`。ref 编号取决于快照顺序；始终使用你自己快照返回的 ref。

记录：固定页面服务器日志、页面加载后的截图。

## 6. 通过 MCP 调用四个工具

MCP 端点是 `http://127.0.0.1:7331/mcp` 上的 streamable HTTP。

### 6.1 初始化并保持会话

```bash
mkdir -p "$EVID"
curl -sS -D "$EVID/init.headers" -o "$EVID/init.json" \
  http://127.0.0.1:7331/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"m1-acceptance","version":"0.1.0"}}}'
cat "$EVID/init.json"
SESSION=$(tr -d '\r' < "$EVID/init.headers" | sed -n 's/^[Mm]cp-[Ss]ession-[Ii]d: *//p')
echo "session=$SESSION"
```

通过标准：HTTP 200，`result.protocolVersion` 为 `2025-06-18`，
`result.serverInfo.name` 存在，响应头带 `Mcp-Session-Id`。守护进程允许不带
session id 的请求，但建议保留，以贴近真实客户端。

定义辅助函数：保存每个响应体，并打印客户端观测到的延迟。初始化之后每个 POST 都携带
`MCP-Protocol-Version`：

```bash
mcp() {
  local name="$1" body="$2"
  curl -sS -o "$EVID/$name.json" \
    -w "$name HTTP %{http_code} in %{time_total}s\n" \
    http://127.0.0.1:7331/mcp \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -H "Mcp-Session-Id: $SESSION" \
    -H 'MCP-Protocol-Version: 2025-06-18' \
    -d "$body"
}
```

确认初始化并列出工具：

```bash
mcp initialized '{"jsonrpc":"2.0","method":"notifications/initialized"}'
mcp tools-list '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

`tools/list` 通过标准：恰好以下四个工具名，每个都有描述、对象类型的
`inputSchema`，以及四个布尔注解（`readOnlyHint`、`destructiveHint`、
`idempotentHint`、`openWorldHint`）：`browser_navigate`、
`page_snapshot`、`browser_click`、`browser_type`。

保存完整的 `tools/list` 响应及其延迟。

### 6.2 browser_navigate

```bash
mcp navigate '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"browser_navigate","arguments":{"url":"http://127.0.0.1:8808/"}}}'
```

期望的 `result.structuredContent`（除 URL 外的字段值每次可能不同）：

```json
{"navigated":true,"loaded":true,"url":"http://127.0.0.1:8808/","previous":"about:blank","same_document":false,"started_at":1763000000000}
```

`result.isError` 必须为 `false`，且 `result.content[0].text` 必须包含相同
JSON。新文档在等待预算内加载完成时 `loaded` 为 `true`；`loaded=false` 仍是
成功结果，表示页面当时尚未加载完。`url` 是重定向后的最终 URL。

**导航时序陷阱。** `browser_navigate` 可能在 新文档加载完成前返回，尤其是在扩展刚
启动或首次加载较慢时。如果 6.3 看到的是上一个页面，等 500 ms 后重新快照。两秒后快照
仍指向旧页面则视为缺陷：记录 navigate JSON（特别是 `loaded`）、快照 JSON，以及
守护进程和 Service Worker 日志。

记录：请求参数、完整响应 JSON、延迟、加载后页面截图，以及一次 `/health` 快照。

通过标准：`navigated=true`，`url` 是固定页面 URL，`loaded=true`（若为
`false` 则按上面的时序说明记录），后续快照识别出固定页面（标题
"Corvus Test Page"）。

### 6.3 page_snapshot

```bash
mcp snapshot '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"interactive"}}}'
```

默认模式是 `interactive`，只保留可操作元素。传 `{"mode":"full"}` 会加入标题、
文本节点和结构内容；`max_nodes`（40..3000）用于限制结果规模。

期望：`url` 为 `http://127.0.0.1:8808/`，`title` 为
`Corvus Test Page`，`node_count` > 0，`nodes` 中包含
`attributes.id="q"` 的 `input`，以及名称为 `Run` 的 `button`，两者都有
形如 `@eN` 的 ref。参考运行返回 7 个节点，`@e1` 对应 `input#q`，
`@e2` 对应 `button#go`。使用你自己响应中的 ref，并记为 `Q_REF` 和
`GO_REF`。

通过标准：URL 和标题正确，两个目标元素都存在且带 ref，`isError` 为 false，
`truncated` 如实报告。可用 ref 是指下一次 click 或 type 能接受它：6.4 的 type
验证 `Q_REF`，6.5 的 click 验证 `GO_REF`。

记录：完整快照 JSON、延迟、两个 ref。

### 6.4 browser_type

```bash
mcp type '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"browser_type","arguments":{"target":"@e1","text":"hello corvus"}}}'
```

把 `@e1` 换成 `Q_REF`。期望如下（`role` 字符串取决于浏览器的可访问性映射；
请断言下面的值，不要依赖 role）：

```json
{"typed":true,"ref":"@e1","selector":null,"tag":"input","role":"textbox","cleared":true,"events":["beforeinput","input","change"],"value_length":11,"url":"http://127.0.0.1:8808/","value":"hello corvus"}
```

然后取一次完整快照，确认输入框的 `attributes.value` 为 `hello corvus`：

```bash
mcp snapshot-after-type '{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"full"}}}'
```

通过标准：`typed=true`，`value` 恰好为 `hello corvus`，`value_length` 为
11，`events` 包含 `beforeinput` 和 `input`（该文本输入框还应出现
`change`），并且至少两秒后的后续快照中值仍然存在。只有密码框会省略 `value`
并返回 `"masked":true`。

记录：type JSON、后续快照 JSON、延迟、填入文本后的截图。

### 6.5 browser_click

```bash
mcp click '{"jsonrpc":"2.0","id":7,"method":"tools/call","params":{"name":"browser_click","arguments":{"target":"@e2"}}}'
```

把 `@e2` 换成 `GO_REF`。期望的 `result.structuredContent`：

```json
{"clicked":true,"ref":"@e2","selector":null,"tag":"button","role":"button","name":"Run","bbox":{"x":0,"y":0,"w":0,"h":0},"point":{"x":0,"y":0},"events":["pointerover","pointerenter","pointermove","pointerdown","mousedown","pointerup","mouseup","click"],"url":"http://127.0.0.1:8808/"}
```

bbox 和 point 的具体值取决于页面；请断言事件序列，不要断言坐标。按钮的 `onclick`
把 `clicked:` 加上 `input#q` 的当前值写入 `p#out`。取一次完整快照：

```bash
mcp snapshot-after-click '{"jsonrpc":"2.0","id":8,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"full"}}}'
```

期望：快照包含文本 `clicked:hello corvus`（`p#out` 下的文本节点），证明点击
执行了，且输入值没有丢失。如果只有 `clicked:` 而没有值，说明 type 步骤失败或输入框
被重置；记录为缺陷。

通过标准：`clicked=true`，八个指针/鼠标事件全部存在，后续快照的 URL 仍是固定页面，
文本为 `clicked:hello corvus`，且 `isError` 为 false。

记录：click JSON、点击后快照 JSON、延迟、显示 `clicked:hello corvus` 的页面截图。

## 7. 负向路径（必须执行）

在正向路径之后执行。记录每个完整响应和延迟。

| 场景 | 请求 | 期望 |
|---|---|---|
| 未知工具 | `tools/call`，`"name":"corvus_missing_tool"` | `result.isError=true`，文本以 `BAD_ARGS:` 开头 |
| 失效引用 | `browser_click`，`{"target":"@e999999"}` | `isError=true`，文本以 `NOT_FOUND:` 开头 |
| 缺少目标 | `browser_click`，`{}` | `isError=true`，文本以 `BAD_ARGS:` 开头 |
| 缺少参数 | `browser_type`，`{"target":"@e1"}`（没有 text） | `isError=true`，文本以 `BAD_ARGS:` 开头 |
| 非法模式 | `page_snapshot`，`{"mode":"everything"}` | `isError=true`，文本以 `BAD_ARGS:` 开头 |
| 越界上限 | `page_snapshot`，`{"max_nodes":10}` | `isError=true`，文本以 `BAD_ARGS:` 开头 |
| 扩展未连接 | 停用扩展，然后调用 `page_snapshot` | `isError=true`，文本以 `TRANSPORT_DOWN:` 开头 |

示例：

```bash
mcp negative-unknown '{"jsonrpc":"2.0","id":20,"method":"tools/call","params":{"name":"corvus_missing_tool","arguments":{}}}'
mcp negative-stale-ref '{"jsonrpc":"2.0","id":21,"method":"tools/call","params":{"name":"browser_click","arguments":{"target":"@e999999"}}}'
mcp negative-missing-target '{"jsonrpc":"2.0","id":22,"method":"tools/call","params":{"name":"browser_click","arguments":{}}}'
mcp negative-missing-text '{"jsonrpc":"2.0","id":23,"method":"tools/call","params":{"name":"browser_type","arguments":{"target":"@e1"}}}'
mcp negative-invalid-mode '{"jsonrpc":"2.0","id":24,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"everything"}}}'
mcp negative-node-cap '{"jsonrpc":"2.0","id":25,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"max_nodes":10}}}'
```

扩展未连接场景：在 `edge://extensions` 停用 Corvus，调用一次快照，然后重新启用。
重新检查 `/health`，确认浏览器在 10 秒内自动重连，且无需重启浏览器。

## 9. 通过标准汇总

| 工具 | 正确性 | 单次延迟预算（本机） |
|---|---|---|
| `browser_navigate` | `navigated=true`；`url` 与请求一致；`loaded=true`；后续快照标题为固定页面 | <= 2000 ms |
| `page_snapshot` | 固定页面 URL/标题；`node_count` > 0；`input#q` 和 `button#go` 有可用 `@eN`；`truncated` 如实报告 | <= 1000 ms（<= 700 节点） |
| `browser_click` | `clicked=true`；八个指针/鼠标/click 事件；页面文本变为 `clicked:hello corvus` | <= 1000 ms |
| `browser_type` | `typed=true`；`value="hello corvus"`；`value_length=11`；出现 input/change 事件；2 秒后不回滚 | <= 1000 ms |
| 负向路径 | `isError=true` 且带文档中的 ErrorCode 前缀；守护进程保持健康 | <= 15000 ms 默认超时 |

出现以下任一情况即判定失败：页面内容错误、ref 缺失、工具返回成功但页面没有任何变化、
错误不是结构化错误、守护进程崩溃，或者在这个本地页面上 click/type/snapshot 超过
3000 ms。

自动化检查是前置条件，不能替代本手册：

```bash
bash tests/conformance/run.sh
```

它通过启动模拟扩展在没有浏览器的情况下验证 MCP 契约。如果默认端口被占用，请用备用端口：

```bash
CORVUS_MCP_URL=http://127.0.0.1:17331/mcp \
CORVUS_WS_URL=ws://127.0.0.1:17330 \
CORVUS_HEALTH_URL=http://127.0.0.1:17331/health \
CORVUSD_ARGS='serve --ws-port 17330 --http-port 17331' \
bash tests/conformance/run.sh
```

## 10. 清理

1. 关闭测试浏览器窗口。
2. 在其终端按 `Ctrl+C` 停止固定页面服务器。
3. 按 `Ctrl+C` 停止守护进程。
4. 确认 HTTP 端口已释放：
   `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:7331/health`
   必须输出 `000`（连接被拒绝）。如果还想证明固定页面服务器已停止，对 8808 端口做同样检查。
5. 保留证据目录；验收结束后不要再修改。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 所有工具返回 `CAPABILITY_UNAVAILABLE` | hello 没有声明 `dom` | 记录 hello/hello_ack；向扩展方提交缺陷 |
| 所有工具返回 `TRANSPORT_DOWN` | 扩展未连接或 Service Worker 休眠 | 检查 `/health` 的 `browsers`；重新打开弹窗；查看 Service Worker 控制台 |
| 脚本化启动后 Edge 扩展始终不出现 | 微软 Edge 忽略 `--load-extension` | 通过 `edge://extensions` 的开发者模式加载，或改用 Chrome/Chromium |
| click/type 返回 `NOT_FOUND` | 使用了导航前的旧 ref | 重新快照并使用新 ref |
| click 返回 `NOT_INTERACTABLE` | 元素被遮挡、在视口外或已禁用 | 滚动到可见区域、关闭浮层或换一个元素 |
| 导航后立即快照仍显示上一页 | navigate 在新文档加载前返回 | 等 500 ms 后重新快照；若持续出现，记录 `loaded` 和时序证据并提交缺陷 |
| `TIMEOUT` | 页面繁忙或弹出了对话框 | 关闭对话框后重试；记录守护进程日志 |
| 7331 连接被拒绝 | 守护进程未运行或端口错误 | 重新执行 `corvusd serve`；检查启动日志 |
| 固定页面 404 或连接被拒绝 | 固定页面服务器未运行 | 执行 `node tests/acceptance/fixtures/serve.mjs` |

## 12. 没有浏览器时的退路

如果环境完全无法运行基于 Chromium 的浏览器，只运行第 9 节的契约检查，并把报告中的真实
浏览器行标记为 NOT RUN。这是部分结果，不是 M1 验收：里程碑要求真实浏览器路径。请在报告
中记录原因和契约检查输出。
