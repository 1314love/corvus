# Corvus M3 acceptance playbook

## 1. Purpose

M3 adds recording, replay and observability to the 26-tool M2 surface, for a
frozen surface of 32 tools. The automated conformance suite proves protocol,
argument, routing, recording and replay behavior against a stateful mock
extension. This playbook is the manual, real-browser acceptance path: a real
Chromium browser with the Corvus extension records MCP sessions in a real SQLite
database, replays a safe recorded step, exports the session, and exposes metrics
and log tails.

Run the automated suite first on isolated ports and a temporary database:

```bash
CARGO=/c/Users/Administrator/.cargo/bin/cargo.exe \
CORVUSD_BIN=./target/debug/corvusd.exe \
CORVUSD_ARGS="serve --db /tmp/corvus-m3-conformance.db --ws-port 29330 --http-port 29331" \
CORVUS_MCP_URL=http://127.0.0.1:29331/mcp \
CORVUS_WS_URL=ws://127.0.0.1:29330 \
CORVUS_METRICS_URL=http://127.0.0.1:29331/metrics \
bash tests/conformance/run.sh
```

Copy the printed RESULT line into the M3 report template. Do not run this suite
on 7330/7331 while a Corvus Windows service is using those ports.

## 2. Scope, sessions and frozen tool names

The 26 M2 tools are unchanged. M3 adds six tools:

| family | tools |
|---|---|
| recording | session_list, session_steps |
| replay | session_replay |
| export | session_export |
| observability | metrics, logs_tail |

Every input schema still has the optional string browser_id from M2b.
session_list, session_steps, session_export, metrics and logs_tail do not need a
browser. session_replay in live mode uses the same browser routing as browser
tools.

Recording rules:

- One MCP session is recorded per HTTP Mcp-Session-Id. Keep the id returned by
  initialize and send it on every request. The database session id is that id.
- Every tools/call is recorded, including failures, with duration, browser_id,
  tab_id, success and error_code.
- Arguments and results are JSON text capped at 262144 bytes. A complete value
  that parses is returned as parsed JSON; otherwise it is returned as the stored
  prefix string. A value above 65536 bytes is returned as null with
  args_truncated or result_truncated and args_bytes or result_bytes.
- session_replay defaults to mode dry_run. Control tools are skipped with reason
  control_tool: session_list, session_steps, session_replay, session_export,
  metrics, logs_tail and browser_list. Live replay also skips tab_close and
  tab_switch with reason tab_tool, and removes the recorded tab_id so the step
  runs on the active tab unless browser_id is supplied.
- A session exists as soon as initialize returns Mcp-Session-Id. At that point
  session_list must show exactly the current session with steps 0 and errors 0,
  not an empty list.
- A session with no replayable step returns BAD_ARGS with
  details.reason no_replayable_steps. An unknown session returns NOT_FOUND with
  details.session_id.

The six M3 tools use 60000 ms command timeouts. Do not invent tool names,
argument keys or error codes.

## 3. Prerequisites

- Windows 10 desktop session with Microsoft Edge. The reference run used
  branded Edge 157.
- The repository at D:/DSH/browser_bridege/corvus.
- Rust at C:/Users/Administrator/.cargo/bin with the offline registry.
- Node.js for the fixture server and JSON checks, and curl for MCP calls.
- A free MCP port pair and a writable temporary SQLite path outside the
  repository. This playbook uses WebSocket 7330, HTTP 7331 and
  /tmp/corvus-m3/corvus.db.
- The extension directory extension/ with manifest.json at its root.
- A desktop session where the browser can stay open.

## 4. Build and start the daemon

From an MSYS bash shell in the repository root:

```bash
export PATH="/c/Users/Administrator/.cargo/bin:$PATH"
mkdir -p /tmp/corvus-m3
export EVID=/tmp/corvus-m3/$(date +%Y%m%d-%H%M%S)
export DB=/tmp/corvus-m3/corvus.db
mkdir -p "$EVID"
cargo build --offline -p corvusd --bin corvusd
./target/debug/corvusd.exe serve --db "$DB" --ws-port 7330 --http-port 7331
```

In a second shell, start the fixture server and read health:

```bash
node tests/acceptance/fixtures/serve.mjs
curl -sS http://127.0.0.1:7331/health
```

The health shape is unchanged. The database file and its -wal and -shm files
are created next to the --db path. corvus doctor prints db_path, schema_version,
sessions and steps counts.

## 6. MCP session and helper

Create the MCP session and keep Mcp-Session-Id:

```bash
export MCP=http://127.0.0.1:7331/mcp
export PROTO=2025-06-18
curl -sS -D "$EVID/init.headers" -o "$EVID/init.json" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "MCP-Protocol-Version: $PROTO" \
  -X POST "$MCP" \
  --data-raw '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"m3-acceptance","version":"1.0"}}}'
export SESSION=$(tr -d '\r' < "$EVID/init.headers" | sed -n 's/^[Mm][Cc][Pp]-[Ss][Ee][Ss][Ss][Ii][Oo][Nn]-[Ii][Dd]:[[:space:]]*//p' | head -n 1)
test -n "$SESSION" || { echo "missing Mcp-Session-Id"; exit 1; }
curl -sS -o "$EVID/notify.json" -w '%{http_code}\n' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "MCP-Protocol-Version: $PROTO" \
  -H "Mcp-Session-Id: $SESSION" \
  -X POST "$MCP" \
  --data-raw '{"jsonrpc":"2.0","method":"notifications/initialized"}'
```

Define a helper:

```bash
ID=100
call() {
  local name="$1" args="$2"
  ID=$((ID + 1))
  curl -sS -o "$EVID/$name.json" -w "$name %{time_total}\n" \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -H "MCP-Protocol-Version: $PROTO" \
    -H "Mcp-Session-Id: $SESSION" \
    -X POST "$MCP" \
    --data-raw "{\"jsonrpc\":\"2.0\",\"id\":$ID,\"method\":\"tools/call\",\"params\":{\"name\":\"$name\",\"arguments\":$args}}"
}
```

If initialize returns no Mcp-Session-Id, stop and report a contract defect:
recording cannot be attributed.

## 7. Baseline: 32 tools, own tab and first calls

Do not drive or close the client's tabs. Create your own tab.

```bash
call tools/list '{}'
node -e 'const r=require(process.argv[1]); const t=r.result.tools; console.log(t.length); console.log(t.map(x=>x.name).sort().join(","));' "$EVID/tools.json"
call session_list '{}'
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; const s=x.sessions.find(v=>v.session_id===process.env.SESSION); if (x.sessions.length!==1||x.total!==1) throw new Error("expected only the current session"); if (!s) throw new Error("current session missing"); if (s.steps!==0||s.errors!==0) throw new Error("initial counters are not zero"); console.log("initial steps=0 errors=0 total=1");' "$EVID/session-list-initial.json"
call browser_list '{}'
call tab_new '{"url":"http://127.0.0.1:8808/m2","active":true}'
export QA_TAB=$(node -e 'const r=require(process.argv[1]); console.log(r.result.structuredContent.tab_id)' "$EVID/tab-new.json")
test -n "$QA_TAB" || { echo "tab_new returned no tab_id"; exit 1; }
call page_snapshot "{\"tab_id\":\"$QA_TAB\",\"mode\":\"interactive\"}"
call page_text "{\"tab_id\":\"$QA_TAB\"}"
call page_find "{\"query\":\"Corvus M2\",\"tab_id\":\"$QA_TAB\"}"
```

The first tools/call in this MCP session must be session_list. A session exists
as soon as initialize returns Mcp-Session-Id, so expect exactly one entry: this
session, steps 0, errors 0, status active, transport http. Do not expect an
empty list; tools/list is not recorded.

After these calls, read session_list again and verify the same session now has
six recorded steps (the initial session_list plus browser_list, tab_new,
page_snapshot, page_text and page_find):

```bash
call session_list '{"limit":20}'
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; const s=x.sessions.find(v=>v.session_id===process.env.SESSION); if (!s) throw new Error("current session missing"); if (s.steps!==6) throw new Error("expected 6 recorded steps, got "+s.steps); console.log("same session steps="+s.steps+" errors="+s.errors);' "$EVID/session-list.json"
```

## 8. Inspect recorded steps

```bash
call session_steps "{\"session_id\":\"$SESSION\",\"limit\":50}"
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; console.log(x.total_steps); for (const s of x.steps) console.log(s.seq,s.tool,s.ok,s.browser_id,s.tab_id);' "$EVID/session-steps.json"
```

Verify:

- seq is strictly ascending and starts at 1.
- Every step has ts, tool, browser_id, tab_id, ok, error_code, duration_ms,
  args, args_truncated, result, result_truncated.
- page_snapshot and tab_new carry your tab_id; browser_list may have tab_id null.
- page_text has parsed args and result, and the result contains the fixture text.
- next_seq appears only when more steps remain. Use from_seq and limit to page.

## 9. Plan and run a replay

A dry run must not touch the browser:

```bash
call session_replay "{\"session_id\":\"$SESSION\",\"mode\":\"dry_run\"}"
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; console.log(x.mode,x.total); console.log(JSON.stringify(x.planned,null,2)); console.log(JSON.stringify(x.skipped,null,2));' "$EVID/replay-dry.json"
```

Expect mode dry_run, a non-empty planned array for browser tools, an empty
executed array, and skipped entries with reason control_tool. No browser call is
made.

Run one safe recorded browser_navigate or page_snapshot step live. Take its
sequence from section 8 and pass the browser id from browser_list:

```bash
export REPLAY_SEQ=6
call session_replay "{\"session_id\":\"$SESSION\",\"from_seq\":$REPLAY_SEQ,\"to_seq\":$REPLAY_SEQ,\"mode\":\"live\",\"browser_id\":\"$BROWSER_ID\"}"
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; console.log(x.mode,x.executed,x.replay_session_id);' "$EVID/replay-live.json"
```

Expect mode live, one executed entry with ok true, and replay_session_id. Then:

```bash
export REPLAY_SESSION=$(node -e 'const r=require(process.argv[1]); console.log(r.result.structuredContent.replay_session_id)' "$EVID/replay-live.json")
call session_list '{"limit":20}'
call session_steps "{\"session_id\":\"$REPLAY_SESSION\",\"limit\":20}"
```

The replay session must exist with agent corvus-replay and transport internal.
Tab tools cannot be replayed.

## 10. Export the session

```bash
call session_export "{\"session_id\":\"$SESSION\"}"
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; const lines=x.content.trim().split(/\r?\n/); console.log(x.format,x.bytes,x.truncated,lines.length); console.log(lines[0]); console.log(lines[1]);' "$EVID/session-export.json"
```

The first JSONL line is type session for this session; every following line is
type step with strictly ascending seq. content is capped at 2097152 bytes and
truncated is true when cut.

## 11. Metrics and the /metrics scrape

Call one user error first, then read metrics:

```bash
call session_steps '{"session_id":"s-does-not-exist"}'
call metrics '{}'
node -e 'const r=require(process.argv[1]); const x=r.result.structuredContent; console.log(JSON.stringify({calls:x.tool_calls_total,errors:x.tool_errors_total,codes:x.errors_by_code,sessions:x.sessions_total,recording:x.recording},null,2));' "$EVID/metrics.json"
```

Verify tool_calls_total is positive, errors_by_code contains NOT_FOUND and
BAD_ARGS with positive counts, sessions_total includes the acceptance and replay
sessions, by_tool has calls/errors/avg_ms, recording.enabled is true and
recording.db_path is the --db path, protocol is the wire protocol version
(1 for this build), and uptime_ms and started_at are present.

Scrape the Prometheus endpoint:

```bash
curl -sS http://127.0.0.1:7331/metrics -o "$EVID/metrics.txt"
grep -E 'corvus_(uptime_seconds|browsers_connected|tool_calls_total|tool_errors_total|sessions_total|steps_total)' "$EVID/metrics.txt"
```

The body is plain Prometheus text and includes corvus_tool_calls_total with a
tool label.

## 12. Log tail

```bash
call logs_tail '{"limit":20}'
call logs_tail '{"limit":20,"level":"info"}'
call logs_tail '{"limit":20,"level":"error"}'
```

Each entry has epoch-millisecond ts, level debug/info/warn/error, target,
message, and a fields object with primitive values stringified. dropped counts
overwritten events. The level filter returns only that level. An invalid level
is BAD_ARGS with details.level.

## 13. Negative and error-path matrix

| case | args | expected |
|---|---|---|
| unknown session in steps | session_steps with session_id s-does-not-exist | NOT_FOUND, details.session_id |
| unknown session in export | session_export with session_id s-does-not-exist | NOT_FOUND |
| unknown session in replay | session_replay with session_id s-does-not-exist | NOT_FOUND |
| empty replayable session | replay a control-only session | BAD_ARGS, details.reason no_replayable_steps |
| bad replay mode | session_replay with mode play | BAD_ARGS |
| reversed window | session_replay with from_seq 9 and to_seq 2 | BAD_ARGS |
| bad steps limit | session_steps with limit 0 | BAD_ARGS |
| bad list limit | session_list with limit 201 | BAD_ARGS |
| bad export format | session_export with format xml | BAD_ARGS |
| bad log level | logs_tail with level verbose | BAD_ARGS, details.level |
| bad log limit | logs_tail with limit 1001 | BAD_ARGS |
| unknown tool | corvus_tool_that_does_not_exist | BAD_ARGS with known tool list |

For the control-only session, create a second MCP session, call only
session_list or tools/list, then replay it. session_list itself is a recorded
control step, so the session has no replayable step.

## 15. Pass criteria per tool

| tool | pass criteria |
|---|---|
| session_list | after initialize, exactly the current session with steps 0 and errors 0; after calls, the same session with steps equal to the calls made, newest-first order, transport http |
| session_steps | strictly ascending seq; parsed args/result for complete values; browser_id and tab_id populated per routing; truncation flags and next_seq correct |
| session_replay | dry_run executes nothing and skips control tools; live executes the selected step, returns replay_session_id, and records a corvus-replay session |
| session_export | first line type session; step lines type step with ascending seq; bytes and truncated coherent |
| metrics | documented counters present; calls and errors advance; recording reports the --db path; errors_by_code includes observed codes |
| logs_tail | entries have the documented shape; level filter works; invalid level is BAD_ARGS |

Hard failures: a missing Mcp-Session-Id, a live replay that changes a client tab,
a replay that executes a control or tab tool, dropped successful calls, or a
/metrics endpoint that does not serve Prometheus text.

## 16. Cleanup and troubleshooting

- Close only your QA tab, then switch back to the tab that was active before
  section 7.
- Clear intercept rules and stop network capture if you used them.
- Stop the daemon with Ctrl-C, then delete the temporary database and its -wal
  and -shm files.
- Stop the fixture server.
- Do not stop or restart a Corvus Windows service on 7330/7331; use isolated
  ports for automated runs.

Troubleshooting:

| symptom | check |
|---|---|
| no Mcp-Session-Id | inspect response headers; M3 recording needs it |
| session_list does not contain the current session after calls | daemon started without --db, or recorder failed; check logs and corvus doctor |
| replay live returns TRANSPORT_DOWN | no browser connected, or wrong browser_id |
| metrics missing | rebuild the daemon; the M3 observability build is required |
| logs_tail empty | call again after a tool call; check the daemon log level |
| database locked | stop the old daemon; remove stale DB and restart one writer |

Never commit the temporary database or evidence directory.
