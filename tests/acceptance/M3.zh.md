# Corvus M3 验收手册

## 1. 目的

M3 在 M2 的 26 个工具之上增加录制、回放与可观测性，形成冻结的 32 个工具。
自动一致性测试套件使用有状态 mock 扩展验证协议、参数、路由、录制与回放行为。
本手册是真实浏览器的人工验收路径：使用已加载 Corvus 扩展的真实 Chromium 浏览器，
把 MCP 会话记录到真实 SQLite 数据库，回放一个安全的已记录步骤，导出会话，
并读取指标与日志尾部。

先在隔离端口和临时数据库上运行自动套件：

```bash
CARGO=/c/Users/Administrator/.cargo/bin/cargo.exe \
CORVUSD_BIN=./target/debug/corvusd.exe \
CORVUSD_ARGS="serve --db /tmp/corvus-m3-conformance.db --ws-port 29330 --http-port 29331" \
CORVUS_MCP_URL=http://127.0.0.1:29331/mcp \
CORVUS_WS_URL=ws://127.0.0.1:29330 \
CORVUS_METRICS_URL=http://127.0.0.1:29331/metrics \
bash tests/conformance/run.sh
```

把打印的 RESULT 行复制到 M3 报告模板。7330/7331 被 Corvus Windows 服务占用时，
不要在该端口上运行此套件。

## 2. 范围、会话与冻结工具名

M2 的 26 个工具保持不变。M3 新增六个工具：

| 类别 | 工具 |
|---|---|
| 录制 | session_list、session_steps |
| 回放 | session_replay |
| 导出 | session_export |
| 可观测性 | metrics、logs_tail |

每个输入 schema 仍带 M2b 引入的可选字符串 browser_id。
session_list、session_steps、session_export、metrics、logs_tail 不需要浏览器。
session_replay 的 live 模式使用与浏览器工具相同的路由。

录制规则：

- 每个 HTTP Mcp-Session-Id 对应一个被录制的 MCP 会话。保留 initialize 返回的 id，
  并在每个请求上发送。数据库中的 session id 就是该 id。
- initialize 返回 Mcp-Session-Id 时会话立即创建。此时 session_list 应显示恰好
  当前会话，steps 与 errors 均为 0，而不是空列表。
- 每个 tools/call 都会记录，包括失败调用，记录耗时、browser_id、tab_id、
  是否成功与 error_code。
- 参数与结果按 JSON 文本保存，各自上限 262144 字节。能够解析且未截断的值按解析后
  JSON 返回；否则返回已保存的前缀字符串。序列化后超过 65536 字节的值返回 null，
  并带 args_truncated 或 result_truncated 以及 args_bytes 或 result_bytes。
- session_replay 默认 mode 为 dry_run。控制工具会以 reason 为 control_tool 跳过：
  session_list、session_steps、session_replay、session_export、metrics、logs_tail
  与 browser_list。live 回放还以 reason 为 tab_tool 跳过 tab_close 与 tab_switch，
  并移除记录的 tab_id，使步骤在活动标签页上执行，除非调用方提供 browser_id。
- 没有可回放步骤的会话返回 BAD_ARGS，details.reason 为 no_replayable_steps。
  未知会话返回 NOT_FOUND，带 details.session_id。

六个 M3 工具使用 60000 ms 的命令超时。不要发明工具名、参数键或错误码。

## 3. 前置条件

- Windows 10 桌面会话与 Microsoft Edge。参考运行使用品牌版 Edge 157。
- 仓库位于 D:/DSH/browser_bridege/corvus。
- Rust 位于 C:/Users/Administrator/.cargo/bin，离线 registry 可用。
- Node.js 用于 fixture 服务与 JSON 检查，curl 用于 MCP 调用。
- 一对空闲 MCP 端口，以及仓库外可写的临时 SQLite 路径。本手册使用
  WebSocket 7330、HTTP 7331 与 /tmp/corvus-m3/corvus.db。
- 扩展目录 extension/，其根目录有 manifest.json。
- 浏览器可以保持打开的桌面会话。

## 4. 构建并启动守护进程

在仓库根目录的 MSYS bash 中：

```bash
export PATH="/c/Users/Administrator/.cargo/bin:$PATH"
mkdir -p /tmp/corvus-m3
export EVID=/tmp/corvus-m3/$(date +%Y%m%d-%H%M%S)
export DB=/tmp/corvus-m3/corvus.db
mkdir -p "$EVID"
cargo build --offline -p corvusd --bin corvusd
./target/debug/corvusd.exe serve --db "$DB" --ws-port 7330 --http-port 7331
```

在第二个 shell 中启动 fixture 服务并读取 health：

```bash
node tests/acceptance/fixtures/serve.mjs
curl -sS http://127.0.0.1:7331/health
```

health 结构不变。数据库文件及其 -wal、-shm 文件创建在 --db 路径旁。
corvus doctor 会打印 db_path、schema_version、sessions 与 steps 计数。

## 5. 加载扩展

1. 打开 edge://extensions。
2. 启用 Developer mode。
3. 选择 Load unpacked，选择 extension/。
4. 确认 Corvus 已启用；弹窗只显示状态，没有 debugger 开关。
5. 如果扩展在守护进程启动前就已加载，请重新加载扩展。

参考扩展 id 为 pdgemoghkehbjpklbmkmchgfmpfghbl。查询 health，确认只有一个已连接
浏览器，capabilities 包含 dom、scripting 与 debugger。
品牌版 Edge 会忽略命令行 --load-extension，请使用 edge://extensions。

## 6. MCP 会话与辅助函数

创建 MCP 会话并保留 Mcp-Session-Id：

```bash
export MCP=http://127.0.0.1:7331/mcp
export PROTO=2025-06-18
curl -sS -D "$EVID/init.headers" -o "$EVID/init.json" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "MCP-Protocol-Version: $PROTO" \
  -X POST "$MCP" \
  --data-raw '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"m3-acceptance","version":"1.0"}}}'
export SESSION=$(tr -d '\r' < "$EVID/init.headers" | sed -n 's/^[Mm][Cc][Pp]-[Ss][Ee][Ss][Ss][Ii][Oo][Nn]-[Ii][Dd]:[[:space:]]*//p' | head -n 1)
test -n "$SESSION" || { echo "missing Mcp-Session-Id"; exit 1; }
curl -sS -o "$EVID/notify.json" -w '%{http_code}\n' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "MCP-Protocol-Version: $PROTO" \
  -H "Mcp-Session-Id: $SESSION" \
  -X POST "$MCP" \
  --data-raw '{"jsonrpc":"2.0","method":"notifications/initialized"}'
```

定义辅助函数：

```bash
ID=100
call() {
  local name="$1" args="$2"
  ID=$((ID + 1))
  curl -sS -o "$EVID/$name.json" -w "$name %{time_total}\n" \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -H "MCP-Protocol-Version: $PROTO" \
    -H "Mcp-Session-Id: $SESSION" \
    -X POST "$MCP" \
    --data-raw "{\"jsonrpc\":\"2.0\",\"id\":$ID,\"method\":\"tools/call\",\"params\":{\"name\":\"$name\",\"arguments\":$args}}"
}
```

如果 initialize 没有返回 Mcp-Session-Id，停止并报告契约缺陷：
录制无法归属到会话。

## 7. 基线：32 个工具、自有标签页与首批调用

不要操作或关闭客户自己的标签页。创建自己的标签页。

```bash
call tools/list '{}'
node -e 'const r=require(process.argv[1]); const t=r.result.tools; console.log(t.length); console.log(t.map(x=>x.name).sort().join(","));' "$EVID/tools.json"
call session_list '{}'
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); const s=x.sessions.find(v=>v.session_id===process.env.SESSION); if (x.sessions.length!==1||x.total!==1) throw new Error("expected only the current session"); if (!s) throw new Error("current session missing"); if (s.steps!==0||s.errors!==0) throw new Error("initial counters are not zero"); console.log("initial steps=0 errors=0 total=1");' "$EVID/session-list-initial.json"
call browser_list '{}'
call tab_new '{"url":"http://127.0.0.1:8808/m2","active":true}'
export QA_TAB=$(node -e 'const r=require(process.argv[1]); console.log(JSON.parse(r.result.content[0].text).tab_id)' "$EVID/tab-new.json")
test -n "$QA_TAB" || { echo "tab_new returned no tab_id"; exit 1; }
call page_snapshot "{\"tab_id\":\"$QA_TAB\",\"mode\":\"interactive\"}"
call page_text "{\"tab_id\":\"$QA_TAB\"}"
call page_find "{\"query\":\"Corvus M2\",\"tab_id\":\"$QA_TAB\"}"
```

本 MCP 会话的第一次 tools/call 必须是 session_list。initialize 返回
Mcp-Session-Id 时会话已创建，因此预期恰好一条：当前会话，steps 为 0、
errors 为 0、status 为 active、transport 为 http。不要预期空列表；
tools/list 不会被记录。

完成这些调用后再次读取 session_list，确认同一会话已有 6 条记录步骤
（首次 session_list 加上 browser_list、tab_new、page_snapshot、page_text
与 page_find）：

```bash
call session_list '{"limit":20}'
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); const s=x.sessions.find(v=>v.session_id===process.env.SESSION); if (!s) throw new Error("current session missing"); if (s.steps!==6) throw new Error("expected 6 recorded steps, got "+s.steps); console.log("same session steps="+s.steps+" errors="+s.errors);' "$EVID/session-list.json"
```

## 8. 检查已记录步骤

```bash
call session_steps "{\"session_id\":\"$SESSION\",\"limit\":50}"
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); console.log(x.total_steps); for (const s of x.steps) console.log(s.seq,s.tool,s.ok,s.browser_id,s.tab_id);' "$EVID/session-steps.json"
```

检查：

- seq 严格递增，从 1 开始。
- 每个步骤都有 ts、tool、browser_id、tab_id、ok、error_code、duration_ms、
  args、args_truncated、result、result_truncated。
- page_snapshot 与 tab_new 带你的 tab_id；browser_list 的 tab_id 可以为 null。
- page_text 有解析后的 args 与 result，result 包含 fixture 文本。
- 只有还有更多步骤时才出现 next_seq。使用 from_seq 与 limit 分页。

## 9. 规划并执行回放

dry run 不得触碰浏览器：

```bash
call session_replay "{\"session_id\":\"$SESSION\",\"mode\":\"dry_run\"}"
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); console.log(x.mode,x.total); console.log(JSON.stringify(x.planned,null,2)); console.log(JSON.stringify(x.skipped,null,2));' "$EVID/replay-dry.json"
```

预期 mode 为 dry_run，浏览器工具的 planned 非空，executed 为空，skipped 中的
条目 reason 为 control_tool。不会发生浏览器调用。

回放一个安全的已记录 browser_navigate 或 page_snapshot 步骤。从第 8 节取得
seq，并传入 browser_list 得到的 browser id：

```bash
export REPLAY_SEQ=6
call session_replay "{\"session_id\":\"$SESSION\",\"from_seq\":$REPLAY_SEQ,\"to_seq\":$REPLAY_SEQ,\"mode\":\"live\",\"browser_id\":\"$BROWSER_ID\"}"
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); console.log(x.mode,x.executed,x.replay_session_id);' "$EVID/replay-live.json"
```

预期 mode 为 live，executed 有一条 ok 为 true 的记录，并返回
replay_session_id。然后：

```bash
export REPLAY_SESSION=$(node -e 'const r=require(process.argv[1]); console.log(JSON.parse(r.result.content[0].text).replay_session_id)' "$EVID/replay-live.json")
call session_list '{"limit":20}'
call session_steps "{\"session_id\":\"$REPLAY_SESSION\",\"limit\":20}"
```

回放会话必须存在，agent 为 corvus-replay，transport 为 internal。
标签页工具不能被回放。

## 10. 导出会话

```bash
call session_export "{\"session_id\":\"$SESSION\"}"
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); const lines=x.content.trim().split(/\r?\n/); console.log(x.format,x.bytes,x.truncated,lines.length); console.log(lines[0]); console.log(lines[1]);' "$EVID/session-export.json"
```

第一行 JSONL 的 type 为 session，对应本会话；其后每一行 type 为 step，
seq 严格递增。content 上限 2097152 字节，被截断时 truncated 为 true。

## 11. 指标与 /metrics 抓取

先制造一个用户错误，再读取 metrics：

```bash
call session_steps '{"session_id":"s-does-not-exist"}'
call metrics '{}'
node -e 'const r=require(process.argv[1]); const x=JSON.parse(r.result.content[0].text); console.log(JSON.stringify({calls:x.tool_calls_total,errors:x.tool_errors_total,codes:x.errors_by_code,sessions:x.sessions_total,recording:x.recording},null,2));' "$EVID/metrics.json"
```

检查 tool_calls_total 为正，errors_by_code 包含 NOT_FOUND 与 BAD_ARGS 且计数为正，
sessions_total 包含验收会话与回放会话，by_tool 每项有 calls/errors/avg_ms，
recording.enabled 为 true，recording.db_path 为 --db 路径，protocol 为线协议版本
（本构建为 1），uptime_ms 与 started_at 存在。

抓取 Prometheus 端点：

```bash
curl -sS http://127.0.0.1:7331/metrics -o "$EVID/metrics.txt"
grep -E 'corvus_(uptime_seconds|browsers_connected|tool_calls_total|tool_errors_total|sessions_total|steps_total)' "$EVID/metrics.txt"
```

响应体是纯 Prometheus 文本，包含带 tool 标签的 corvus_tool_calls_total。

## 12. 日志尾部

```bash
call logs_tail '{"limit":20}'
call logs_tail '{"limit":20,"level":"info"}'
call logs_tail '{"limit":20,"level":"error"}'
```

每个条目有毫秒时间戳 ts、level（debug/info/warn/error）、target、message，
以及 fields 对象，字段值为字符串化后的原始类型。dropped 是启动以来被覆盖的
事件数。level 过滤只返回该级别。非法 level 返回 BAD_ARGS，details.level。

## 13. 负向与错误路径矩阵

| 场景 | 参数 | 预期 |
|---|---|---|
| steps 未知会话 | session_steps，session_id 为 s-does-not-exist | NOT_FOUND，details.session_id |
| export 未知会话 | session_export，session_id 为 s-does-not-exist | NOT_FOUND |
| replay 未知会话 | session_replay，session_id 为 s-does-not-exist | NOT_FOUND |
| 空可回放会话 | 回放只含控制工具的会话 | BAD_ARGS，details.reason 为 no_replayable_steps |
| 非法回放模式 | session_replay，mode 为 play | BAD_ARGS |
| 反向窗口 | session_replay，from_seq 9、to_seq 2 | BAD_ARGS |
| steps 非法 limit | session_steps，limit 为 0 | BAD_ARGS |
| list 非法 limit | session_list，limit 为 201 | BAD_ARGS |
| export 非法格式 | session_export，format 为 xml | BAD_ARGS |
| 非法日志级别 | logs_tail，level 为 verbose | BAD_ARGS，details.level |
| 非法日志 limit | logs_tail，limit 为 1001 | BAD_ARGS |
| 未知工具 | corvus_tool_that_does_not_exist | BAD_ARGS，带已知工具列表 |

对于只含控制工具的会话：新建第二个 MCP 会话，只调用 session_list 或
tools/list，然后回放它。session_list 本身也是被记录的控制步骤，
因此该会话没有可回放步骤。

- init.headers、init.json、notify.json。
- tools.json、browser-list.json、tab-new.json。
- session-list-initial.json、session-list.json、session-steps.json。
- replay-dry.json、replay-live.json、session-export.json 及可选的

- metrics.json、metrics.txt、logs-default.json、logs-info.json、

- 第 13 节每一行对应的负向 JSON。
- 回放前后的页面截图，以及 edge://extensions 的截图。
- 从一致性套件复制的 RESULT 行。

## 15. 各工具通过标准

| 工具 | 通过标准 |
|---|---|
| session_list | initialize 后恰好一条当前会话，steps 与 errors 均为 0；调用后同一会话 steps 等于已发起的调用数，按最新优先排序，transport 为 http |
| session_steps | seq 严格递增；完整值解析为 args/result；按路由填入 browser_id 与 tab_id；截断标志与 next_seq 正确 |
| session_replay | dry_run 不执行任何步骤并跳过控制工具；live 执行选中步骤并返回 replay_session_id；记录 corvus-replay 会话 |
| session_export | 第一行 type session；step 行 type step 且 seq 递增；bytes 与 truncated 一致 |
| metrics | 文档化计数存在；调用与错误增长；recording 报告 --db 路径；errors_by_code 含观察到的错误码 |
| logs_tail | 条目符合文档结构；level 过滤有效；非法 level 为 BAD_ARGS |

硬性失败：缺少 Mcp-Session-Id；live 回放改变客户标签页；回放执行控制工具或
标签页工具；成功的调用丢失记录；/metrics 不返回 Prometheus 文本。

## 16. 清理与故障排查

- 只关闭自己的 QA 标签页，然后切回第 7 节之前处于活动状态的标签页。
- 如果使用过拦截规则或网络捕获，请清除并停止。
- 用 Ctrl-C 停止守护进程，然后删除临时数据库及其 -wal、-shm 文件。
- 停止 fixture 服务。
- 不要停止或重启 7330/7331 上的 Corvus Windows 服务；自动运行使用隔离端口。

故障排查：

| 现象 | 检查 |
|---|---|
| 没有 Mcp-Session-Id | 检查响应头；M3 录制需要它 |
| 调用后 session_list 缺少当前会话 | 守护进程未带 --db 启动，或录制失败；检查日志与 corvus doctor |
| replay live 返回 TRANSPORT_DOWN | 没有浏览器连接，或 browser_id 错误 |
| metrics 缺失 | 重新构建守护进程；需要 M3 可观测性构建 |
| logs_tail 为空 | 工具调用后重试；检查守护进程日志级别 |
| 数据库被锁定 | 停止旧守护进程；删除过期数据库，仅保留一个写入者 |

不要提交临时数据库或证据目录。
