# Corvus M1 acceptance playbook

Status: executable playbook for milestone M1. Audience: a QA operator who has
never seen this repository. The primary path drives a real browser through the
MCP endpoint and records evidence for all four M1 tools. Follow the steps in
order.

## 1. Scope

M1 proves one real path end to end:

```
MCP client  ->  corvusd  ->  extension  ->  Chromium  ->  web page
            <-           <-            <-          <-
```

The only tools in scope are the four frozen M1 tools:

| tool | purpose |
|---|---|
| `browser_navigate` | load an http/https/file URL and wait for the new document; report `loaded` and the final `url` |
| `page_snapshot` | dump the page as a compact DOM + accessibility tree with `@eN` refs |
| `browser_click` | click a `@eN` ref or a CSS selector with a full pointer/mouse event sequence |
| `browser_type` | type into a text field or contenteditable element with native setters and input events |

Argument shapes are frozen for M1: `browser_navigate {url, tab_id?}`,
`page_snapshot {tab_id?, mode?: "interactive" | "full" (default "interactive"),
max_nodes?: 40..3000}`, `browser_click {target, tab_id?}`, and
`browser_type {target, text, clear? (default true), blur?, tab_id?}`.
`target` is a snapshot reference such as `@e12` or a CSS selector.

Everything else in the requirements document is out of scope for this run.

## 2. What you need

- Windows 10 or later. Commands are shown for MSYS bash; macOS/Linux
  equivalents work with the matching binary paths.
- Rust 1.82 or newer and Cargo. On the reference machine Cargo is
  `C:/Users/Administrator/.cargo/bin/cargo.exe` and is not on `PATH`; use the
  absolute path or add it to `PATH`.
- `curl` and `bash`. `node` is used by the local fixture server and is
  optional only for pretty-printing JSON.
- A Chromium-based browser. The reference environment is branded Microsoft
  Edge 157. Chrome or Chromium 120+ also works, but the load procedure differs:
  branded Edge ignores the command-line `--load-extension` switch, so load the
  folder through `edge://extensions`. Use Chrome or Chromium when you need a
  scripted launch.
- A normal desktop session with the browser window visible. Do not run this on
  a locked or disconnected screen: click dispatch uses element hit-testing.
- No internet access is required. The acceptance page is a local fixture.

## 3. Build and start the daemon

From the repository root:

```bash
cargo build --offline -p corvusd
```

Drop `--offline` if the machine has registry access. Start the daemon:

```bash
./target/debug/corvusd.exe serve
```

(On macOS/Linux: `./target/debug/corvusd serve`.)

Expected startup log lines on stderr:

```
websocket transport listening addr=127.0.0.1:7330
mcp http listening url=http://127.0.0.1:7331/mcp
```

Check health in a second terminal:

```bash
mkdir -p tests/report/evidence/$(date +%F)
EVID=tests/report/evidence/$(date +%F)
curl -s http://127.0.0.1:7331/health | tee "$EVID/health-before.json"
```

Expected shape: `version`, `protocol` = `2025-06-18`, `ws_addr` =
`127.0.0.1:7330`, `http_addr` = `127.0.0.1:7331`, and `browsers` =
`[]` until step 4 completes. Record this JSON as evidence.

Leave the daemon running. If a port is already in use, stop the other daemon
instead of starting a second one, or start this daemon explicitly on alternate
ports (`serve --ws-port 17330 --http-port 17331`) and use those ports below.

## 4. Load the extension unpacked in Edge

1. Open `edge://extensions` in the browser.
2. Enable **Developer mode**.
3. Click **Load unpacked** and select the `extension/` directory of this
   repository (the directory that contains `manifest.json`).
4. Confirm the Corvus card appears with no errors. Note the extension ID on the
   card. The reference unpacked path produced
   `pdgemoghkehbjpklbmkmchgfmpfghbl`; an ID derived from a different path is
   expected to differ, so record the actual ID.
5. Open the service worker console (`Inspect views: service worker`) and
   confirm hello / hello_ack log lines and no uncaught exceptions. Open the
   toolbar popup: it is status-only, and the status dot must show connected.
   The debugger channel is automatic; there is no switch to flip.
6. Re-run the health check:
   `curl -s http://127.0.0.1:7331/health | tee "$EVID/health-after.json"`.
   `browsers` must now contain one entry with `id`, `profile`,
   `extension_version`, `capabilities`, and `connected_at_ms`. On the
   reference run the id was `edge:33628f01180d3d48` and the capabilities were
   `["dom","scripting"]`. The capability list must contain `dom`.

If `browsers` stays empty, the extension did not complete the hello handshake.
If it contains a browser but no `dom` capability, stop and record the exact
hello and hello_ack frames: every M1 tool will answer
`CAPABILITY_UNAVAILABLE`.

Record: browser name and version, extension ID, the `browsers` array from
`/health`, and a screenshot of the extensions page.

## 5. Serve the local acceptance page

In a third terminal, start the fixture server:

```bash
node tests/acceptance/fixtures/serve.mjs
```

Expected output: `serving http://127.0.0.1:8808/`. Open
`http://127.0.0.1:8808/` once in the test browser to confirm the page renders.
The fixture contains:

| element | purpose |
|---|---|
| `h1#h` "Corvus E2E" | page identity |
| `input#q` with placeholder "type here" | target for `browser_type` |
| `button#go` "Run" | target for `browser_click`; writes `clicked:<value>` into `p#out` |
| `p#out` initially "idle" | visible proof that click ran with the typed value |
| `a#lnk` "Jump" and `p#sec` | extra interactive content and a same-page link |

The reference run's interactive snapshot returned 7 nodes with `@e1` on
`input#q` and `@e2` on `button#go`. Ref numbering is snapshot-order
dependent; always use the refs returned by your own snapshot.

Record: fixture server log and a screenshot of the loaded fixture page.

## 6. Drive the four tools over MCP

The MCP endpoint is streamable HTTP at `http://127.0.0.1:7331/mcp`.

### 6.1 Initialize and keep a session

```bash
mkdir -p "$EVID"
curl -sS -D "$EVID/init.headers" -o "$EVID/init.json" \
  http://127.0.0.1:7331/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"m1-acceptance","version":"0.1.0"}}}'
cat "$EVID/init.json"
SESSION=$(tr -d '\r' < "$EVID/init.headers" | sed -n 's/^[Mm]cp-[Ss]ession-[Ii]d: *//p')
echo "session=$SESSION"
```

Pass criteria: HTTP 200, `result.protocolVersion` is `2025-06-18`,
`result.serverInfo.name` is present, and the response carries an
`Mcp-Session-Id` header. The daemon accepts requests without the session id,
but keep it for realism.

Define a helper that saves each response body and prints the client-observed
latency. `MCP-Protocol-Version` is sent on every POST after initialization:

```bash
mcp() {
  local name="$1" body="$2"
  curl -sS -o "$EVID/$name.json" \
    -w "$name HTTP %{http_code} in %{time_total}s\n" \
    http://127.0.0.1:7331/mcp \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -H "Mcp-Session-Id: $SESSION" \
    -H 'MCP-Protocol-Version: 2025-06-18' \
    -d "$body"
}
```

Acknowledge initialization and list tools:

```bash
mcp initialized '{"jsonrpc":"2.0","method":"notifications/initialized"}'
mcp tools-list '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Pass criteria for `tools/list`: exactly these four names, each with a
description, an object `inputSchema`, and all four annotation booleans
(`readOnlyHint`, `destructiveHint`, `idempotentHint`,
`openWorldHint`): `browser_navigate`, `page_snapshot`, `browser_click`,
`browser_type`.

Record the full `tools/list` response and its latency.

### 6.2 browser_navigate

```bash
mcp navigate '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"browser_navigate","arguments":{"url":"http://127.0.0.1:8808/"}}}'
```

Expected `result.structuredContent` (field values other than the URL vary per
run):

```json
{"navigated":true,"loaded":true,"url":"http://127.0.0.1:8808/","previous":"about:blank","same_document":false,"started_at":1763000000000}
```

`result.isError` must be `false` and `result.content[0].text` must carry
the same JSON. `loaded` is `true` when the new document completed within the
wait budget; `false` is a successful result that means the page was still
busy. `url` is the final URL after redirects.

**Navigate timing pitfall.** `browser_navigate` may return before the new
document has finished loading, particularly right after the extension starts
or on a slow first load. If 6.3 shows the previous page, wait 500 ms and take
the snapshot again. A snapshot that still identifies the old page after two
seconds is a defect: record the navigate JSON (especially `loaded`), the
snapshot JSON, and the daemon/service-worker logs.

Record: request arguments, full response JSON, latency, a screenshot of the
loaded page, and a follow-up `/health` snapshot.

Pass criteria: `navigated=true`, `url` is the fixture URL, `loaded=true`
(or `false` with the timing note above), and a follow-up snapshot identifies
the fixture (title "Corvus Test Page").

### 6.3 page_snapshot

```bash
mcp snapshot '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"interactive"}}}'
```

The default mode is `interactive`, which keeps actionable elements only.
Passing `{"mode":"full"}` adds headings, text nodes and structural content;
`max_nodes` (40..3000) bounds the result.

Expected: `url` is `http://127.0.0.1:8808/`, `title` is
`Corvus Test Page`, `node_count` > 0, and `nodes` contains an
`input` with `attributes.id="q"` and a `button` whose name is `Run`,
each with a ref of the form `@eN`. The reference run returned 7 nodes,
`@e1` for `input#q` and `@e2` for `button#go`. Use the refs from your
own response and record them as `Q_REF` and `GO_REF`.

Pass criteria: correct URL and title, both target elements present with refs,
no `isError`, and `truncated` reported honestly. A usable ref is one that
the next click or type accepts; the type call in 6.4 proves `Q_REF` and the
click call in 6.5 proves `GO_REF`.

Record: full snapshot JSON, latency, and the two refs.

### 6.4 browser_type

```bash
mcp type '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"browser_type","arguments":{"target":"@e1","text":"hello corvus"}}}'
```

Replace `@e1` with `Q_REF`. Expected (the `role` string depends on the
browser's accessibility mapping; assert the values below, not the role):

```json
{"typed":true,"ref":"@e1","selector":null,"tag":"input","role":"textbox","cleared":true,"events":["beforeinput","input","change"],"value_length":12,"url":"http://127.0.0.1:8808/","value":"hello corvus"}
```

Then take a full snapshot and confirm the input's `attributes.value` is
`hello corvus`:

```bash
mcp snapshot-after-type '{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"full"}}}'
```

Pass criteria: `typed=true`, `value` is exactly `hello corvus`,
`value_length` is 12, `events` contains `beforeinput` and `input` (a
`change` event is expected for this text input), and the value is still
present in the follow-up snapshot at least two seconds later. A password field
is the only case where `value` is omitted and `masked:true` is returned.

Record: type JSON, follow-up snapshot JSON, latency, and a screenshot of the
filled field.

### 6.5 browser_click

```bash
mcp click '{"jsonrpc":"2.0","id":7,"method":"tools/call","params":{"name":"browser_click","arguments":{"target":"@e2"}}}'
```

Replace `@e2` with `GO_REF`. Expected `result.structuredContent`:

```json
{"clicked":true,"ref":"@e2","selector":null,"tag":"button","role":"button","name":"Run","bbox":{"x":0,"y":0,"w":0,"h":0},"point":{"x":0,"y":0},"events":["pointerover","pointerenter","pointermove","pointerdown","mousedown","pointerup","mouseup","click"],"url":"http://127.0.0.1:8808/"}
```

The bbox and point values are page-specific; assert the event sequence, not the
coordinates. The button's `onclick` writes `clicked:` plus the current value
of `input#q` into `p#out`. Take a full snapshot:

```bash
mcp snapshot-after-click '{"jsonrpc":"2.0","id":8,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"full"}}}'
```

Expected: the snapshot contains the text `clicked:hello corvus` (a text node
under `p#out`), proving that the click ran and that the typed value survived.
If it says `clicked:` with no value, the type step failed or the field was
reset; record it as a defect.

Pass criteria: `clicked=true`, all eight pointer/mouse events present, the
follow-up snapshot URL is still the fixture and the text is
`clicked:hello corvus`, and no `isError`.

Record: click JSON, after-click snapshot JSON, latency, and a screenshot of the
page showing `clicked:hello corvus`.

## 7. Negative paths (required)

Run these after the happy path. Capture each full response and latency.

| case | request | expected |
|---|---|---|
| unknown tool | `tools/call` with `"name":"corvus_missing_tool"` | `result.isError=true`, text starts `BAD_ARGS:` |
| stale ref | `browser_click` with `{"target":"@e999999"}` | `isError=true`, text starts `NOT_FOUND:` |
| missing target | `browser_click` with `{}` | `isError=true`, text starts `BAD_ARGS:` |
| missing arg | `browser_type` with `{"target":"@e1"}` (no text) | `isError=true`, text starts `BAD_ARGS:` |
| invalid mode | `page_snapshot` with `{"mode":"everything"}` | `isError=true`, text starts `BAD_ARGS:` |
| out-of-range cap | `page_snapshot` with `{"max_nodes":10}` | `isError=true`, text starts `BAD_ARGS:` |
| no extension | disable the extension, then `page_snapshot` | `isError=true`, text starts `TRANSPORT_DOWN:` |

Example:

```bash
mcp negative-unknown '{"jsonrpc":"2.0","id":20,"method":"tools/call","params":{"name":"corvus_missing_tool","arguments":{}}}'
mcp negative-stale-ref '{"jsonrpc":"2.0","id":21,"method":"tools/call","params":{"name":"browser_click","arguments":{"target":"@e999999"}}}'
mcp negative-missing-target '{"jsonrpc":"2.0","id":22,"method":"tools/call","params":{"name":"browser_click","arguments":{}}}'
mcp negative-missing-text '{"jsonrpc":"2.0","id":23,"method":"tools/call","params":{"name":"browser_type","arguments":{"target":"@e1"}}}'
mcp negative-invalid-mode '{"jsonrpc":"2.0","id":24,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"mode":"everything"}}}'
mcp negative-node-cap '{"jsonrpc":"2.0","id":25,"method":"tools/call","params":{"name":"page_snapshot","arguments":{"max_nodes":10}}}'
```

For the no-extension case, disable Corvus on `edge://extensions`, run a
snapshot, then re-enable it. Re-run `/health` and confirm the browser
reconnects within 10 seconds without a browser restart.

## 9. Pass criteria summary

| tool | correctness | latency budget (single run, local) |
|---|---|---|
| `browser_navigate` | `navigated=true`; `url` equals the request; `loaded=true`; follow-up snapshot has the fixture title | <= 2000 ms |
| `page_snapshot` | fixture URL/title; `node_count` > 0; usable `@eN` refs for `input#q` and `button#go`; `truncated` reported honestly | <= 1000 ms for <= 700 nodes |
| `browser_click` | `clicked=true`; all eight pointer/mouse/click events; page text becomes `clicked:hello corvus` | <= 1000 ms |
| `browser_type` | `typed=true`; `value="hello corvus"`; `value_length=12`; input/change events; no rollback after 2 s | <= 1000 ms |
| error paths | `isError=true` with the documented ErrorCode prefix; daemon stays healthy | <= 60000 ms default timeout |

Hard fail for any of: wrong page content, missing refs, a tool that returns
success while doing nothing, an unstructured error, a daemon crash, or a
latency above 3000 ms for click/type/snapshot on this local page.

The automated harness is a prerequisite, not a substitute:

```bash
bash tests/conformance/run.sh
```

It checks the MCP contract without a browser by starting a mock extension. If
the default ports are occupied, run it on alternate ports:

```bash
CORVUS_MCP_URL=http://127.0.0.1:17331/mcp \
CORVUS_WS_URL=ws://127.0.0.1:17330 \
CORVUS_HEALTH_URL=http://127.0.0.1:17331/health \
CORVUSD_ARGS='serve --ws-port 17330 --http-port 17331' \
bash tests/conformance/run.sh
```

## 10. Cleanup

1. Close the test browser window.
2. Stop the fixture server (`Ctrl+C` in its terminal).
3. Stop the daemon with `Ctrl+C`.
4. Confirm the HTTP ports are free:
   `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:7331/health`
   must print `000` (connection refused). Do the same for port 8808 if you
   want to prove the fixture server stopped.
5. Keep the evidence directory; do not edit it after the run.

## 11. Troubleshooting signatures

| symptom | likely cause | action |
|---|---|---|
| every tool returns `CAPABILITY_UNAVAILABLE` | hello did not offer `dom` | record hello/hello_ack; file a defect against the extension |
| every tool returns `TRANSPORT_DOWN` | extension not connected or service worker asleep | check `/health` `browsers`; reopen the popup; check the service worker console |
| Edge extension never appears after a scripted launch | branded Edge ignores `--load-extension` | load through `edge://extensions` with Developer mode, or use Chrome/Chromium |
| click/type returns `NOT_FOUND` | ref taken before a navigation or stale | take a fresh snapshot and use the new ref |
| click returns `NOT_INTERACTABLE` | element covered, offscreen, or disabled | scroll it into view, close overlays, or choose another element |
| snapshot immediately shows the previous page | navigate resolved before the new document loaded | wait 500 ms, snapshot again; record `loaded` and the timing as a defect if it persists |
| `TIMEOUT` | page busy or dialog open | close the dialog, retry; record the daemon log |
| connection refused on 7331 | daemon not running or wrong port | restart `corvusd serve`; check the startup log |
| fixture page 404 or connection refused | fixture server not running | start `node tests/acceptance/fixtures/serve.mjs` |

## 12. Fallback when no browser is available

If the environment cannot run a Chromium-based browser at all, run only the
contract harness in section 9 and mark the real-browser rows of the report as
NOT RUN. That is a partial result, not M1 acceptance: the milestone requires a
real browser path. Record the reason and the harness output in the report.
