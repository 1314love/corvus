## 6. Precedence, batch policy and error taxonomy

- read_only denies every non-read-only tool, including browser_click and the whole browser_batch call, while allowing browser_list and read-only page tools. read_only takes precedence over allow_tools.
- allow_tools restricts the callable set; deny_tools wins when a tool appears in both lists (the policy itself rejects that overlap at startup, so runtime precedence is exercised with disjoint lists).
- Denials are typed POLICY_DENIED, the 11th public error code, with retryable=false. MCP returns an isError content result with no structuredContent; REST returns HTTP 403 with the same code and details.
- Exact MCP prefix observed: POLICY_DENIED: tool browser_click denied by guardrails policy (read_only), followed by the JSON details. Details are {reason, tool, policy} for tool denials and {reason, url, policy} for URL denials. The policy value is present in details, but not in /health.
- The extension error/type surface accepts all 11 codes, maps POLICY_DENIED to retryable=false, and renders the localized policy-denied message plus a sanitized reason.
- The conformance suite now includes a real denial check: MCP browser_click returns isError plus POLICY_DENIED and read_only, the REST call returns 403 with POLICY_DENIED and retryable=false, and /health shows guardrails enabled without the policy path. That check passed 14/14 on ports 29412/29413 and is one of the 137 conformance results.

## 7. Host and navigation gate

The host gate applies to browser_navigate, tab_new and the final URL of navigation/history results. With allowed_hosts set, only http and https URLs whose host matches an exact entry or a '*.suffix' entry (including the suffix apex itself) are allowed; ports are ignored; about:blank is always allowed. file, data and javascript URLs have no matching host and are denied while an allowlist is active. Without an allowlist, block_private_network separately rejects literal localhost, *.localhost, *.local, loopback/private/link-local/unspecified IPv4, and IPv6 unique-local, link-local and IPv4-mapped private addresses. No DNS resolution is performed.

Static coverage passed for exact host, wildcard host including apex and a deep subdomain, port-insensitive matching, about:blank, file/data/javascript denial, all tested private IPv4 and IPv6 forms with reason private_network, and a public host allowed. The allowlist check precedes the private-network check, so an unlisted private host reports host_not_allowed rather than private_network.

Live coverage passed on both CDP and extension channels: browser_navigate to a host outside the allowlist returns POLICY_DENIED; tab_new to an unlisted host is denied before dispatch; http://localhost:8811 is denied by the allowlist; tab_new about:blank passes the guardrail and only then reports TRANSPORT_DOWN with no browser. A /redirect route returning 302 to http://localhost:8813/guardrails.html was denied after load with reason redirect_not_allowed, and browser_history reload of that final URL was denied with the same reason. The final URL remained the localhost landing URL. The backward-slash URL https://evil.test\@127.0.0.1/ was denied as host_not_allowed; a case such as example.com\@127.0.0.1 parses as host example.com under the WHATWG URL rules and is not a host-gate bypass.

## 13. Limitations and residual risk

1. The navigation guard is a URL policy, not a network sandbox. It does not filter subresources, fetch/XHR, WebSocket, service-worker traffic or requests initiated by page script. Egress controls are still required for a hostile page.
2. Host checks use the literal parsed host and do not resolve DNS. A public name that resolves to a private address (DNS rebinding) is not detected by this policy; documentation states that egress controls are required.
3. browser_eval and page_html can still read page-reachable data. The content boundary wraps tool output; it does not remove the page's access to its own data or prevent a caller from asking for it.
4. Boundary escaping is exact-string escaping of the two raw markers. Homoglyphs, Unicode normalization variants or other marker-like strings are not normalized.
5. redact_secrets is scoped to browser_cookies. Password inputs are always masked, but there is no general secret scanner for arbitrary page text, form fields or response bodies.
6. content_boundary is scoped to page_snapshot compact text, page_text.text and page_html.html. JSON snapshots, page_find and browser_console are intentionally unwrapped.
7. read_only depends on the shared tool metadata and guarded dispatch. A future tool added without correct metadata could be misclassified; the 43-tool catalogue and its metadata must be reviewed with each tool addition.
8. The policy is loaded once at startup. Changing the file requires a restart; there is no live reload.
9. Authentication is off by default on loopback. The local auth store is in memory, so bootstrap users and refresh-token state do not survive a restart; access JWTs remain valid until expiry. Binding to a non-loopback address without auth is refused unless --allow-no-auth is explicitly passed.
10. The documented browser_type masked marker is per-channel: extension returns masked=true for a password field, CDP returns no value and no masked flag. This is a Low documentation/contract limitation, not a secret leak.
11. The write-scope matrix used one Windows host, one headless Chrome build and isolated daemon ports. It did not use the user's Edge 9222, a live daemon, a real deployment or an NFR-3 endurance run, and it does not claim 72-hour availability.
12. Acceptance was performed on an uncommitted working tree at HEAD 61ca85fbf5af3e4acd830ef4b8254272f3fed0a8. Release edits remain uncommitted; signing, packaging and deployment are out of QA scope.
13. The conformance contract snapshot remains tests/conformance/schema-snapshot.v1.5.0.json by design; v1.6.0 adds no tool and no input-schema shape change. This is not a missed re-baseline.
14. The M2b regression uses a temporary harness adapted to the committed fixture's button-driven fetch page; the product fixture and server were not changed.
