## 6. Snapshot diff semantics

page_snapshot diff is compact-only. format=json with diff=true returns the exact typed error page_snapshot diff is only supported with compact format. The application layer computes the diff once per call from a baseline cache keyed by browser, session and tab; extension and CDP share the same grammar and browser_batch applies the same treatment exactly once.

On tests/acceptance/fixtures/diff-page.html the first diff:true call returned baseline=true. The CDP run returned unchanged 1, changed 1, added 1, removed 1 in 4 lines; the extension run returned unchanged 2, changed 1, added 1, removed 1 in 5 lines because the extension includes one additional text line. Markers were exactly one "  ", one "+ ", one "~ " and one "- " line; Gamma stayed unchanged, Alpha 2 was "~ ", Beta was "- " and Delta was "+ ". A second diff:true call was byte-identical and did not refresh the baseline.

diff:false refreshed the baseline to 3 or 4 unchanged lines; a following diff:true returned all unchanged with baseline=true. A URL change returned baseline=false with all counts 0 and unmarked text. A second isolated tab also returned baseline=false with all counts 0, confirming the tab component of the cache key. browser_batch page_snapshot with diff returned the same diff exactly once and did not double-apply it.

## 12. Defects, fixes and limitations

Fixed and verified during acceptance:

- **CDP frame counters included the top document (High, task-120).** The contract requires child-only total/included. QA measured 4/3 on CDP against the extension 3/2, reported the mismatch, and task-120 fixed crates/corvus-cdp/src/tools.rs. The final CDP run returns total 3, included 2, skipped f1 cross_origin, and omits frames when no child frame exists. The frame and diff harness passes 49/49 on forced CDP and pure extension.
- **Pre-fix Rust gate and extension README format (process).** The final gate is clean at 220 tests. A dirty extension README failed format check; the whitespace-only correction was applied outside QA scope, and the rerun passed 41 tests and check-build.

Recorded limitations:

- The auth store is in-memory: bootstrap accounts and refresh tokens are lost on restart; stateless access JWTs remain valid until expiry. A persistent auth store is not part of 1.5.0.
- Auth is off by default on loopback. Public binds require auth or an explicit --allow-no-auth; the opt-out logs a warning and is not recommended for production.
- Cross-channel tab-id and ref bridging is not implemented; both directions return typed BAD_ARGS. Extension refs are @eN and CDP refs are @cN.
- When max_nodes is exhausted before a later frame is traversed, the truncated snapshot metadata only includes frames reached before the budget stop; the tested global-budget run placed the cross-origin frame before the overflow and returned complete 3/2/1 metadata. This truncated edge is recorded, not treated as a 1.5.0 release blocker.
- The first auto-channel alltools run hit a transient download_list/download_wait race and returned 38/40; the immediate rerun returned 40/40. The forced and pure runs passed on the first attempt.
- M2b regression used a temporary harness adaptation to the committed fixture; no product code or committed fixture was changed.
- One host, one Chrome for Testing build, and no real external browsers. No live deployment, no Docker/Kubernetes runtime test and no 72-hour NFR-3 soak were performed.
- The working tree is dirty and uncommitted; the Lead owns the final commit, tag and release. This report is not a release signature.
