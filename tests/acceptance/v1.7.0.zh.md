# Corvus 1.7.0 验收报告

## 1. 目的与结论

**PASS。** 冻结的 v1.7.0 62 工具范围在保留原有 44 个工具及其 schema 字节不变的前提下，新增 18 个覆盖 page、input、tabs、storage 与 diagnostics 的工具。两条通道、42 个 handler 的扩展构建、全部新工具族、batch 策略、护栏、录制、协议与打包预期均已在冻结树上验证。验证期间发现的 3 个 Medium 问题和 1 个 High 问题均已修复并复测；没有未关闭的 High 或 Medium 问题。该 High 问题为扩展被动掩码泄漏：password 输入值进入 `page_snapshot` JSON/compact、`page_find`、`page_forms` 与 `page_accessibility`；修复后已在两条通道独立复测。第 7 与第 13 节披露一项端到端证据缺口：32 MiB 的 page_pdf 上限未能通过真实工具调用触达，因为 headless 浏览器在渲染超大随机画布页面时终止；该上限仍由 Rust 拒绝路径及单元测试覆盖。

## 13. 限制与范围

- 32 MiB `page_pdf` 上限未端到端触达：超大随机画布页面在 `Page.printToPDF` 返回前使 headless Chrome 崩溃。单元测试与代码路径覆盖拒绝逻辑，但这不是真实上限 PASS。
- 护栏 host gate 是应用层导航检查，不是网络沙箱。解析到私有地址的公网主机名在未做 DNS 解析时不会被拦截，DNS rebinding 仍不在范围内。
- 即使启用 content boundary 包装，`browser_eval` 与 `page_html` 仍可暴露页面可达数据。该边界是提示注入标记，不是数据防泄漏控制。
- Content boundary 包装适用于 compact `page_snapshot` 文本、`page_text.text` 与 `page_html.html`；JSON snapshot、`page_find` 与控制台输出不做包装。
- 截图与 PDF 像素既不脱敏也不做 boundary 包装。表单/snapshot 输出中的 password 会掩码，但可见秘密仍可能出现在图像或 PDF 中。
- 被动密码掩码覆盖 snapshot、find、forms、accessibility 及其录制结果。`page_html` 与 `browser_eval` 是显式原始提取工具，仍可能返回页面中的 password 值。调用方提供的搜索 query 会作为 `page_find` 参数写入录制，即使结果为空；这是输入来源，不是页面数据泄漏。
- `redact_secrets` 当前覆盖 `browser_cookies` 结果以及新的 cookie/storage 录制形状；其他页面数据不受影响。
- Read-only 策略执行依赖工具元数据。截图与 PDF 是只读工具，在 `read_only` 下有意允许；如需阻止请使用 `deny_tools`。
- 策略只在启动时加载。修改策略文件需要重启 daemon。
- 认证状态在内存中。重启会重建 bootstrap 账号并使 refresh token 失效；重启前的 access token 在过期前仍然有效。
- CDP `page_accessibility` 在较小 `max_depth` 下可能只返回 root，因为有效节点位于 generic 包装之后；这符合契约但粒度较粗。
- CDP `health.browser_count` 与 `connected_browsers` 统计的是扩展注册表，而非已连接的 CDP 浏览器；CDP `cookie_set` 在缺少 Domain 属性时以空字符串省略 `domain`，扩展则报告有效 host。二者是 Low 通道一致性观察，不是失败。
- Headless Chrome 会把 `window_new` 请求的尺寸钳制为现有 1280x800 窗口；这是环境限制，不是产品契约失败。
- 测试使用单台 Windows 主机、隔离端口与 headless Chrome/Edge。未执行真实浏览器、实时 daemon、NFR-3 72 小时 soak 或多主机部署。工作树未提交；本报告描述工作树，不是已发布 tag。
- 本轮无策略覆盖为两条通道各 49 项 snapshot 探针；较旧的 auto 通道 29/40 遗留工具 harness 未针对 62 工具范围重跑。
