## 8. 批处理与跨通道约定

browser_batch 位于 page 分类。20 步上限、stop_on_error 默认 true、递归调用 browser_batch 拒绝、daemon 控制类 allowlist 拒绝均返回类型化 BAD_ARGS。混合通道步骤会执行扩展步骤，并对 CDP-only 步骤返回 CAPABILITY_UNAVAILABLE，而不是中止整个 batch。结果形状为 {ok,count,stopped,results}；停止后的步骤不出现。

跨通道 tab id 不做桥接：扩展数字 id 传给 CDP 工具、32 位十六进制 CDP target id 传给扩展-only 工具，均返回带提示的类型化 BAD_ARGS。省略 tab_id 使用 active tab，可正常工作。完整桥接仍是 v1.4 的已记录限制。

## 13. 缺陷、修复与限制

验收期间已修复并验证：

- **重连后 CDP target 缓存陈旧（High，task-107）。** 修复方式：断开时清空 targets、sessions 与 active_target；从当前 page target 修复 active target；陈旧 id 映射为类型化 NOT_FOUND。QA 复现原 kill/relaunch 与 channel-switch 序列，确认无陈旧 id、无 INTERNAL -32602，page_snapshot/page_text 正常。
- **task-107 进行中代码的格式化门禁（Low，流程）。** backend2 已格式化两个 Rust 文件；最终独立 fmt 门禁为 0。

已记录限制：

- 认证仓库在内存中：bootstrap 账号与 refresh token 在重启后丢失；无状态 access JWT 在过期前仍有效。持久化认证仓库不属于 1.4.0。
- loopback 默认关闭认证。公网 bind 必须启用认证或显式 --allow-no-auth；该 opt-out 会输出 warning，不建议生产使用。
- 未实现跨通道 tab-id 与 ref 桥接；两个方向均返回类型化 BAD_ARGS。扩展引用为 @eN，CDP 引用为 @cN。
- 扩展构建的生成契约文件仍引用 tests/conformance/schema-snapshot.v1.3.0.json。该快照与新 v1.4.0 快照逐字节相同（43 工具）；一致性测试本身使用 v1.4.0 快照。
- M2b 回归使用针对已提交 fixture 的临时 harness 适配；未修改产品代码或已提交 fixture。
- 仅一台主机、一个 Chrome for Testing 构建、无真实外部浏览器。未做线上部署、Docker/Kubernetes 运行时测试，也未做 72 小时 NFR-3 长稳。
