## 6. 优先级、Batch 策略与错误分类

- read_only 拒绝所有非只读工具，包括 browser_click 与整个 browser_batch 调用，同时允许 browser_list 与只读页面工具。read_only 优先于 allow_tools。
- allow_tools 限制可调用集合；deny_tools 在两者同时出现时优先（策略启动时会拒绝该重叠，因此运行时优先级用不相交列表验证）。
- 拒绝为类型化 POLICY_DENIED，第 11 个公共错误码，retryable=false。MCP 返回 isError 内容结果且无 structuredContent；REST 返回 HTTP 403，携带相同 code 与 details。
- 观察到的 MCP 前缀：POLICY_DENIED: tool browser_click denied by guardrails policy (read_only)，后接 JSON details。工具拒绝 details 为 {reason, tool, policy}，URL 拒绝为 {reason, url, policy}。details 中出现 policy 值，但 /health 不出现。
- 扩展错误/类型层接受全部 11 个 code，将 POLICY_DENIED 映射为 retryable=false，并渲染本地化 policy-denied 消息及净化后的 reason。
- 一致性测试已加入真实拒绝检查：MCP browser_click 返回 isError 加 POLICY_DENIED 与 read_only，REST 调用返回 403 加 POLICY_DENIED 与 retryable=false，/health 显示 guardrails enabled 但不含策略路径。该检查在端口 29412/29413 通过 14/14，并计入 137 个一致性结果之一。

## 7. 主机与导航门禁

主机门禁作用于 browser_navigate、tab_new 以及导航/history 结果的最终 URL。设置 allowed_hosts 时，只允许 host 精确匹配或匹配 '*.suffix'（含 suffix apex 本身）的 http 与 https URL；端口被忽略；about:blank 始终允许。allowlist 生效时，file、data、javascript URL 没有匹配 host，因此被拒绝。未设置 allowlist 时，block_private_network 另行拒绝字面 localhost、*.localhost、*.local、回环/私有/链路本地/未指定 IPv4，以及 IPv6 唯一本地、链路本地与 IPv4 映射私有地址。不做 DNS 解析。

静态覆盖通过：精确主机、通配主机（含 apex 与深层子域）、端口无关匹配、about:blank、file/data/javascript 拒绝、所有测试的私有 IPv4/IPv6 形式且 reason 为 private_network、公网主机允许。allowlist 检查先于私有网络检查，因此未列出的私有主机报告 host_not_allowed，而非 private_network。

live 覆盖在 CDP 与扩展通道均通过：browser_navigate 到 allowlist 外主机返回 POLICY_DENIED；tab_new 到未列出主机在 dispatch 前被拒；http://localhost:8811 被 allowlist 拒绝；tab_new about:blank 通过 guardrail，之后才因无浏览器报告 TRANSPORT_DOWN。/redirect 路由返回 302 到 http://localhost:8813/guardrails.html，加载后以 reason redirect_not_allowed 被拒；browser_history 重新加载该最终 URL 同样以 redirect_not_allowed 被拒。最终 URL 保持 localhost landing URL。反斜杠 URL https://evil.test\@127.0.0.1/ 作为 host_not_allowed 被拒；example.com\@127.0.0.1 这类形式在 WHATWG URL 规则下解析为 host example.com，不属于主机门禁绕过。

## 9. Batch 与 Session Replay

- deny_tools [browser_click] 且 stop_on_error 默认 true 时，browser_batch page_text -> browser_click -> page_text 返回 stopped:true 与两个结果项。被拒步骤携带 error.code POLICY_DENIED、retryable=false、reason deny_list；该步骤从未 dispatch，fixture click 状态保持 not-clicked。
- read_only 下，browser_batch 本身在任何步骤被考虑前即被拒绝。
- Session replay 干跑规划允许的 tab_new 与 page_text 步骤，将 browser_click 列入 skipped，reason policy_denied、retryable=false，未执行任何步骤。

- Replay 使用共享 guarded dispatch 路径，因此策略在顶层、browser_batch 内与 session replay 中恰好应用一次。未观察到重复拒绝记录或重复执行。

## 13. 限制与残余风险

1. 导航 guard 是 URL 策略，不是网络沙箱。它不过滤子资源、fetch/XHR、WebSocket、service-worker 流量或页面脚本发起的请求。面对敌意页面仍需出口控制。
2. 主机检查使用字面解析 host，不做 DNS 解析。解析到私有地址的公网域名（DNS rebinding）不会被该策略发现；文档已说明需要出口控制。
3. browser_eval 与 page_html 仍可读取页面可达数据。内容边界只包裹工具输出，不会移除页面对其自身数据的访问，也不能阻止调用方请求这些数据。
4. 边界转义只针对两个原始标记做精确字符串转义。同形字、Unicode 规范化变体或其他类似标记的字符串不会被规范化。
5. redact_secrets 仅作用于 browser_cookies。password input 始终掩码，但没有针对任意页面文本、表单字段或响应体的通用秘密扫描器。
6. content_boundary 仅作用于 page_snapshot compact text、page_text.text 与 page_html.html。JSON 快照、page_find 与 browser_console 有意不包裹。
7. read_only 依赖共享工具元数据与 guarded dispatch。未来新增工具若元数据不正确，可能被错误分类；每次新增工具都必须审查 43 工具目录及其元数据。
8. 策略只在启动时加载。修改文件需要重启；没有 live reload。
9. 默认在回环地址关闭认证。本地 auth store 在内存中，bootstrap 用户与 refresh-token 状态不跨重启保留；access JWT 在过期前仍有效。绑定非回环地址且未启用 auth 时，除非显式传入 --allow-no-auth，否则拒绝启动。
10. 文档化的 browser_type masked 标记按通道不同：扩展对 password 字段返回 masked=true，CDP 不返回值也不返回 masked 标志。这是 Low 级文档/契约限制，不是秘密泄漏。
11. 验收矩阵使用一台 Windows 主机、一个 headless Chrome 构建和隔离 daemon 端口。未使用用户 Edge 9222、线上 daemon、真实部署或 NFR-3 耐久性运行，也不声称 72 小时可用性。
12. 验收在 HEAD 61ca85fbf5af3e4acd830ef4b8254272f3fed0a8 的未提交工作树上执行。发布改动仍未提交；签名、打包与部署不在 QA 范围内。
13. 一致性契约快照仍为 tests/conformance/schema-snapshot.v1.5.0.json，这是有意的；v1.6.0 未新增工具或输入 schema 形状。这不是遗漏的重新基线。
14. M2b 回归使用适配已提交 fixture 按钮式 fetch 页面的临时 harness；产品 fixture 与服务器未改动。
