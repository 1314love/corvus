## 8. Guardrail and defect acceptance carried into the release

- `read_only` allowed `browser_screenshot` and denied a mutating tool; `deny_tools` returned `POLICY_DENIED`.
- The passive password leak in the extension `page_snapshot` path was fixed and independently retested: no `topsecret` in JSON/compact snapshots, `page_find`, `page_forms` or `page_accessibility`; labeled password inputs keep their label and masked value; non-password values are unchanged.
- CDP `page_forms` returns form name, id, action and method as strings even when controls use those names.
- The extension `page_links` default no longer includes a zero-area anchor; `include_hidden: true` still does.
- Extension `browser_navigate` from a fresh `about:blank` tab now succeeds; HTTP/HTTPS behavior is unchanged.
- Screenshot and PDF finalization runs once, writes unique files and stores no base64 in session recording; replay skips non-replayable file captures.

## 9. Known limits

- The live 32 MiB `page_pdf` cap was not reached end to end; the largest live PDF was 55,891 B. The Rust rejection path and its unit test cover the cap, so this verification does not claim a live cap pass.
- The local Windows ZIP and its report are local evidence, not published assets. The published Windows, Linux and checksum assets are CI rebuilds from tag `v1.7.0`.
- QA acceptance and packaging evidence were measured on the frozen 62-tool tree at HEAD `d804c33`, before release commit `f12930c`. The committed tree differs only by the release commit itself; published assets come from `f12930c`.
- Screenshot pixels and PDF bytes are not redacted, inspected or boundary-wrapped.
- `tab_group`, `tab_duplicate`, `window_list` and `window_new` are extension-only; forced CDP returns `CAPABILITY_UNAVAILABLE`.
- No live 1.7.0 deployment is claimed, and NFR-3 (72 hours) remains unpassed.
- The external QA evidence directory is not committed; the reports and selected evidence paths are committed.
