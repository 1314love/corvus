## Known limitations

- REST auth accounts and refresh tokens are in memory in 1.4.0 and reset on
  restart. Persistent auth storage is future work.
- The bearer guard covers `/api/v1` only. `/mcp`, the extension WebSocket,
  legacy `/health`, `/metrics`, `/api-docs/openapi.json` and `/docs` are
  unauthenticated even when local auth is on.
- The checked-in Kubernetes Deployment passes `--allow-no-auth`; it starts but
  is explicitly unauthenticated. MCP remains unauthenticated.
- NFR-3 is not passed. The 72-hour soak remains incomplete after the earlier
  stop at about eight hours; 1.4.0 is not soak certified.
- Firefox remains unsupported (NFR-6 deviation unchanged).
- CDP is loopback-only and unauthenticated. The shipped Docker image and
  Kubernetes manifests contain no browser and cannot reach browser loopback on
  the host.
- Forced `cdp` has no extension fallback. macOS has no packaged installer;
  Linux packaging is x86_64 only.
- During the first packaging check, the browser launch briefly attached CDP to
  the user's Edge instance on port 9222 without an MCP or REST call or any
  navigation; it was stopped and rerun isolated.
- Extension tab ids and CDP target ids remain separate namespaces;
  cross-channel references return typed `BAD_ARGS`.
- No live 1.4.0 deployment is claimed. The development machine continued to run
  the existing 1.0.0 service with the user's normal Edge.
