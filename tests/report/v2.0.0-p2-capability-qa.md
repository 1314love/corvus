- 303 functional checks passed and 0 failed across seven matrices.

- All Rust and extension gates exited 0: Rust 321 tests passed, 0 failed, 1 ignored; extension 13 files and 89 tests plus 1 E2E test passed.

- The built extension was loaded unmodified and completed a real, encrypted handshake to the real Rust daemon. All ten tools then executed through that live extension.
- The dynamic tool list changed correctly on stdio, including quiet disconnects that must not produce a notification.

The PASS applies only to source HEAD f5a3a5ed471995e9f0ccd201366d2951583fafae and the artifact hashes in section 4. It does not certify the legacy 1.x surface, a released product, or production deployment.

## 8. Tool contract and capability semantics

The ten public tools appear in this order: browser_status, tab_list, tab_open, tab_close, page_navigate, page_read, page_snapshot, element_click, element_type, page_screenshot.

Confirmed contract behavior:

- bootstrap exposes only browser_status, with the exact instructions "Browser tools appear when a browser session is connected. Use browser_status to see available groups." and HTTP listChanged false.
- With a full provider, exactly the ten ordered tools appear. With no session, browser_status returns count 0, four capabilities false, and the exact no-session hint.
- Unknown tools return BAD_ARGS. Known but currently hidden tools return CAPABILITY_UNAVAILABLE.
- Group availability requires all actions of that group. Input additionally requires page. If a provider advertises an incomplete group, no partial tools from that group appear.
- Total tool counts were exactly 10 (all groups), 9 (no capture), 8 (no input), 7 (no tabs), 5 (no page, input also disappears), 2 (no page and no tabs), and 1 (no groups).
- tab_open/close, page_navigate explicit and default tab selection, page_read text/html plus truncation, snapshot refs, click, type, and full_page refusal all match the spec.
- Tool errors are MCP isError true with one text block shaped as {"error":{"code":"...","message":"..."}}. Unknown provider error codes normalize to INTERNAL. Error and result messages contain no provider, extension, CDP, plugin, worker, WebSocket, ws, or channel wording.
- With two browser sessions, omitting browser_id for an action returns AMBIGUOUS_BROWSER; browser_status without browser_id lists both sessions and aggregate capabilities and never returns AMBIGUOUS_BROWSER.

5. page_screenshot full_page is a P3 capability and returns CAPABILITY_UNAVAILABLE in P2.
6. page_pdf is not part of the P2 ten-tool surface. Legacy 1.x limits for it were not revalidated.
7. The extension package version remains 1.7.0 because v2.0 is not released.
8. Browser support was exercised with Chrome 157 headless. Other browser families were not part of this frozen P2 matrix.
9. Cross-origin iframe and best-effort shadow-DOM behavior remain the documented best-effort limits; the tested fixture covered ordinary content and open shadow DOM.
10. The provider registry is in-memory. Reconnect and replacement behavior was tested, but multi-process persistence is not a P2 claim.
