## 7. Limits

- NFR-3 is not passed; the 72-hour soak stopped after about eight hours. No 72-hour certification is claimed.
- No live 1.5.0 deployment is claimed. The local 1.0.0 service was already absent and was not started for this release.
- Firefox remains unsupported; the NFR-6 deviation is unchanged.
- CDP endpoints are loopback-only and unauthenticated. Docker and Kubernetes images ship no browser and cannot reach host loopback.
- The Docker job builds and checks the image; no registry publication is claimed. Kubernetes manifests receive static CI checks, not a managed-cluster deployment.
- A forced CDP channel has no fallback to the extension.
- macOS has no packaged installer; Linux packaging supports x86_64.
- Auth accounts and refresh tokens are in memory and do not survive a restart; REST authentication does not cover `/mcp`, the extension WebSocket or Swagger.
- Extension tab ids and CDP tab ids remain separate namespaces; there is no cross-channel tab or ref bridge.
- Snapshot diffs are compact-only; JSON with `diff` returns typed `BAD_ARGS`.
- Cross-origin frame content is skipped and never read.
- QA and installer acceptance were measured on the frozen working tree before the release commit. The local installer ZIP is not a CI rebuild and is not the published Windows asset.
- The release process found and corrected a Git stat-cache staging omission (eleven metadata files) in the follow-up commit. Future release commits should force-stage with `git add --renormalize .` or compare index blobs with `git hash-object` before tagging.

## 8. Sign-off

Corvus 1.5.0 is published, its CI and release workflows succeeded, and all three published assets were independently verified against their recorded SHA-256 values. The release meets its recorded acceptance and packaging gates with the limits above.
