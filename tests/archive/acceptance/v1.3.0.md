# Corvus v1.3.0 Acceptance — 43 Tools, Compact Snapshots and CDP Parity

## 1. Purpose and scope

This document records QA acceptance of the v1.3.0 token-efficiency iteration on the frozen product tree. It covers the 43-tool catalogue, the compact snapshot format and exact line grammar on both the extension and CDP channels, JSON compatibility, viewport and bbox options, node caps and truncation, stable refs, CDP actions and page_find, cross-channel ref typing, browser_batch, auto and explicit channel behaviour, pure-extension fallback, reconnect and event regression, the updated conformance suite, and the existing M3/M4/M2b regressions.

The tree was tested at workspace version 1.3.0. Testing was code-level and test-environment-level only:

- No live deployment, production service change, or 72-hour NFR-3 claim.
- The live Corvus service on 7330/7331 and the user's Edge on CDP 9222 were not used for commands.
- The isolated daemon used 29330/29331 and dedicated headless Chrome for Testing profiles, with CDP on 9333 for auto and 9444 for explicit.
- Only temporary extension copies were edited. Product extension files and crates/ were not edited by QA.

Format checks:

- Compact lines use the documented fixed order: @ref role "name" [states] value="..." bbox=x,y,w,h.
- Names, values and text are escaped and truncated at 120, 80 and 240 characters respectively.
- States are limited to disabled, checked, mixed, focused, required, expanded and selected.
- Full mode emits # "text" lines and truncates text at 240 characters.
- JSON mode keeps the backward-compatible page_snapshot object: url, title, viewport, mode, node_cap, node_count, element_count, text_count, ref_count, truncated, nodes.
- Compact result carries format: compact, tab_id, url, title, viewport, mode, node_count, truncated and text.
- Interactive and full modes were both exercised, as were default and explicit format values.
- Empty generic elements are omitted in full mode; this is documented and was accounted for by injecting text-bearing nodes for cap tests.

## 6. Refs, bbox, viewport and truncation

- CDP refs are @c<backendNodeId>; extension refs are @e<number>. Both were unique and stable across repeated snapshots in the same document.
- A click and type using @c refs from page_find and page_snapshot succeeded on the committed fixtures.
- include_bbox adds bbox only when requested. CDP bbox coverage was live 3/3, m2 12/15 and m2b 4/4. The live textbox sample bbox 57,93,177,21 matched the element layout.
- viewport_only with full mode returned live 11 of 13, m2 21 of 59 and m2b 18 of 18. The off-screen live section at y=1410 was excluded, confirming task-94 viewport semantics.
- viewport_only with interactive mode can return all interactive nodes when every interactive control is above the fold. This is correct; the harness asserts the full-mode subset and the off-screen element.
- max_nodes accepted 40, 300 and 700. With 1,200 injected text divs, node_count was exactly 40, 300 and 700, truncated was true, and compact text was 817, 4,261 and 9,461 bytes respectively on CDP.
- The extension truncation run measured 616, 3,933 and 9,133 text bytes for the same caps.
- Invalid caps and invalid formats return typed BAD_ARGS. No silent clamping to an undocumented value was observed.

Task-94 was a real pre-fix defect: CDP DOMSnapshot did not request includeDOMRects, so CDP include_bbox could be absent and viewport_only could return zero. Backend2 fixed snapshot_inputs to request includeDOMRects and verified layout-bounds semantics. QA reran all affected checks after the fix; the results above are from the frozen tree, not the pre-fix build.
