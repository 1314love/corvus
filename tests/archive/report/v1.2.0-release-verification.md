# Corvus v1.2.0 release verification

Status: released. Tag v1.2.0 and the GitHub Release were published on 2026-11-15; CI, the release workflow and the published assets were verified independently and are recorded below.

## Release scope

- Version: 1.2.0 (workspace Cargo.toml, Cargo.lock local packages, extension manifest).
- Hybrid transport: the extension detects a browser CDP endpoint, the daemon prefers direct CDP and keeps a long-lived browser WebSocket; when no CDP endpoint is available it uses the extension transport.
- Programmatic channel control through `auto`, `cdp` and `extension` modes, exposed by `browser_channel` and the daemon flags `--channel`, `--cdp-endpoint` and `--no-cdp`.
- CDP tools: `cdp_status`, `cdp_targets`, `cdp_send`, `cdp_events`, `browser_console`, `browser_cookies`, `browser_dialog` and `browser_emulate`.
- MCP surface: 42 tools, each carrying a category; brief and full `tools/list` views; `tool_help`.
- Bilingual documentation, changelog and release notes.

## Limitations

- NFR-3 is not passed. The clean 72-hour soak was stopped at the client's request after about eight hours; 1.2.0 is not 72-hour soak certified.
- Firefox remains unsupported (NFR-6 deviation unchanged). Supported browsers are Edge, Chrome and Brave (Chromium 120+).
- CDP is loopback-only and unauthenticated; a browser-level endpoint can control every profile in that browser instance. Never expose 9222, 9223 or 9333.
- The shipped Docker image and Kubernetes manifests contain no browser and cannot reach browser loopback on the host. The image is not published to an image registry; Kubernetes checks in CI are static checks, not a hosted-cluster deployment.
- Forced `cdp` never falls back, so extension-only tools require the extension and a shared tool may fail when the CDP route is unavailable.
- macOS has no packaged installer; Linux packaging is x86_64 only.
- Extension tab ids and CDP target ids use different namespaces. 1.2.0 returns typed `BAD_ARGS` hints; full bridging is deferred to 1.3.
- Changing an explicitly configured extension CDP endpoint while the daemon is connected may require a daemon restart. Auto-discovered endpoint changes are re-polled and reconnect automatically.
- No live 1.2.0 deployment is claimed. The packaging host still runs the existing 1.0.0 service because the user's normal Edge browser was connected; 1.2.0 was accepted on isolated daemons and a throwaway service instead.
