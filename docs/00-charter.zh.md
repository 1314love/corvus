## 1. 为什么做

浏览器自动化长期被一个假设锁住：操作浏览器的是陌生人，所以每一次点击都要授权，每一个下载都要挂起，每一个敏感字段都要人工放行。这套假设在「陌生脚本」场景里是必要的；但当操作者是已经在你机器上工作、持有你账号权限的 AI 代理时，它只剩下摩擦——人会疲劳，审批会被无脑点过，而真正的风险信号被淹没在噪声里。

Corvus 的结论不是「再收紧一次」，而是换一个假设：**浏览器是 AI 的器官，不是它造访的沙箱。**

在这个假设下，产品的第一功能不是安全而是连接与能力：永不掉线、零审批、工具要全、一切可观测。当连接、能力、可观测性都做到位时，安全性来自架构本身（本机回环、按用户隔离、可审计回放），而不是来自打断用户。

## 2. 产品理念（2026-11-14 定稿）

1. 浏览器是 AI 的器官。器官不需要每次使用都申请授权。
2. 没有页面。除了一个只有开关的极小弹窗，扩展不提供任何界面。
3. 永不掉线。连接是产品的第一功能，不是错误处理。
4. 工具要全。不是「够用」，是「AI 能对浏览器做的每一件事」。
5. 一切可观测。每一次命令、每一帧页面、每一次网络请求都可记录、可回放。
6. 工程量不是约束，钱不是约束。质量与上限才是约束。

## 3. 目标

| 编号 | 目标 | 度量 |
|---|---|---|
| G1 | 永不掉线 | 连续 72 小时压测，命令成功率 >= 99.9%，断连自愈中位时间 < 1s |
| G2 | 零摩擦 | 安装到首个命令 < 60s，全程 0 次人工审批弹窗 |
| G3 | 能力完整 | >= 60 个 MCP 工具，覆盖感知 / 动作 / 网络 / 存储 / 调试五类 |
| G4 | 全可观测 | 100% 命令可回放，录制开销 < 5% CPU |
| G5 | 多客户端 | 主流 MCP 客户端开箱即用：Claude Code、Cursor、DSH、Cline、Copilot、LangChain |

## 4. 非目标（本期不做）

- 不做云端浏览器集群（那是 Browserbase 的战场）。
- 不做可视化流程编排器（录制是为了排障与复现，不是为了搭工作流）。
- 不做移动端浏览器控制。
- 不做企业级多租户与审计合规。本项目假定：单机、单用户、用户即最高权限。

## 6. 关键决策记录

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-11-14 | 后端语言 Rust（替代最初的 Go 设想） | 零 GC 停顿的并发、单二进制分发、与 CDP/WS 生态契合 |
| 2026-11-14 | 形态是「本地服务 + 扩展回连」 | 必须控制用户正在使用的浏览器；纯 CDP 需要重启或独立 profile，因此被排除 |
| 2026-11-14 | 取消一切审批与配对 | 托管型 AI 场景下，安全边界应由操作系统用户承担 |
| 2026-11-14 | 保留极简弹窗，仅一个 debugger 开关 | debugger 权限会在浏览器顶部常驻横幅，需随时可关 |
| 2026-11-14 | 源码公开，但禁止商用（PolyForm Noncommercial 1.0.0） | 代码开放共享，但不允许他人商用；商用需单独授权 |
| 2026-11-14 | 产品名 Corvus（渡鸦） | 渡鸦是会用工具、能记人脸、会为未来做计划的鸟；恰好是「会侦察、会记忆、会动手」的代理隐喻 |

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| MV3 Service Worker 30s 休眠导致连接丢失 | 高 | offscreen 文档保活 + alarms 看门狗 + daemon 侧主动重连 |
| debugger 权限常驻横幅、易被用户误关 | 中 | 默认关闭，弹窗一键切换，关闭时自动降级到纯 DOM 通道 |
| 多浏览器扩展 id 不一致 | 中 | 用 manifest key 固定扩展 id，安装器统一分发 |
| 录制数据膨胀 | 中 | 分片 + 压缩 + 保留策略，默认只记结构化事件不记全帧 |
| 客户端 MCP 实现差异 | 中 | 以 MCP 2025-06-18 规范为准，提供 stdio 与 HTTP 双栈与自检命令 |
