## 发布内容

发布增加由守护进程执行的可选本地守护策略，并为策略拒绝提供本地化扩展错误；不新增 MCP 工具。目录仍为 43 个工具、九个类别。发布已作为 GitHub 发布 446071476 上线。

## 守护策略

策略文件为严格 JSON，最大 65,536 字节，要求 `version: 1`，可选字段为 `read_only`、`allow_tools`、`deny_tools`、`allowed_hosts`、`block_private_network`、`redact_secrets` 与 `content_boundary`。未知字段、未知工具名、允许/拒绝列表重叠以及无效主机模式都会在启动时致命失败。schema、主机模式语法与三个示例见 [11-guardrails.zh.md](../11-guardrails.zh.md)。

工具检查先只读、再允许列表、最后拒绝列表。URL 门禁在分发前检查 `browser_navigate` 与 `tab_new` 的参数，并在 `browser_navigate`、`tab_new` 与 `browser_history` 返回后复查 URL。`about:blank` 始终允许；`allowed_hosts` 要求 http 或 https 并拒绝后缀伪装；私有网络阻断基于字面量，从不解析 DNS。

通过 `--guardrails <PATH>` 或 `CORVUS_GUARDRAILS=<PATH>` 启用。无效策略以 invalid-input 错误中止守护进程启动；策略正文不会被记录。

## 执行与错误面

`crates/corvusd/src/lib.rs` 的 `RouterBackend::call` 在分发前检查工具策略与导航参数。被拒调用会被记录，并返回错误而不触达浏览器。门禁位于守护进程侧；扩展不评估策略。

`browser_batch` 检查每个步骤，默认在第一次拒绝时停止；批次不能绕过嵌套步骤的策略。`session_replay` 检查每个计划或实况步骤，并把被拒步骤记录为 reason 为 `policy_denied` 的跳过项。

拒绝使用第 11 个错误码 `POLICY_DENIED`，`retryable: false`。工具拒绝消息为 `tool <name> denied by guardrails policy (<reason>)`；URL 拒绝消息为 `navigation denied by guardrails policy (<reason>)`。详情携带原因与策略源路径。

REST 返回 HTTP 403，错误体嵌套在 `error` 下。分发后的 URL 拒绝仍报告 `POLICY_DENIED`，但导航已经发生。

## 密钥脱敏与内容边界

启用 `redact_secrets` 后，`browser_cookies` 结果顶层 `cookies` 数组中每个含 `value` 字段的对象都会变成 `value: "[redacted]"` 并带 `redacted: true`。其他工具、嵌套值、请求头与页面文本不会被脱敏。

启用 `content_boundary` 后，`page_text` 的文本、`page_html` 的 HTML 与紧凑 `page_snapshot` 的文本会用精确的 Corvus 不可信内容标记包裹。内嵌标记会先被转义，因此最终值恰好有一个前导与一个尾随标记。JSON 快照不受影响。

密码掩码独立于守护策略：快照中的密码值渲染为 `***`。`browser_type` 因通道而异：扩展对密码字段返回 `masked: true`，其他输入返回截断的 `value`；CDP 不返回 `value`，也不返回 `masked`，因此不会返回输入值。

## 扩展行为

当守护进程返回 `POLICY_DENIED` 时，Vue 界面显示本地化的 `errors.policyDenied` 消息，或带已清洗原因的 `errors.policyDeniedWithReason`。它绝不显示策略源路径，也不提供重试操作。

扩展改动仅涉及呈现。它不在本地解析、缓存或执行守护策略，也不新增权限或处理器。

## 工具面

MCP 目录不变：43 个工具、九个类别。本工作不新增工具、不删除工具，也不因守护策略改变工具输入；策略拒绝通过既有错误信封返回。

## 通道矩阵

| 模式 | 传输 | 回退 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | 已连接时用 CDP，否则用扩展 | 仅当 CDP 路由为 Unsupported | 扩展仍是零配置路径 |
| `cdp` | 仅浏览器级 CDP 直连 | 无 | 覆盖全部 33 个浏览器类工具 |
| `extension` | 仅扩展 | 无 | 覆盖 25 个浏览器类工具 |

通道可用性与 1.5.0 相同。CDP 仍仅限宿主机回环且没有认证；守护策略对两个通道同等适用。

## 架构

十个 crate 不变：`corvus-domain`、`corvus-application`、`corvus-api`、`corvus-proto`、`corvus-mcp`、`corvus-transport`、`corvus-record`、`corvus-cdp`、`corvusd` 与 `corvus`。守护策略位于守护进程内，不新增 crate。

`crates/corvusd/src/guardrails.rs` 持有策略模型、解析、主机匹配、URL 检查、脱敏与边界包裹。`crates/corvusd/src/lib.rs` 的 `RouterBackend::call`、`run_batch` 与 `session_replay` 是执行点。

没有新增 crate、没有 REST 路由变更、没有录制 schema 变更。守护策略是显式启用的；未配置策略时，1.5.0 架构保持不变。

## 部署与健康检查

运维人员传入 `--guardrails` 或设置 `CORVUS_GUARDRAILS`。守护进程在开始服务前拒绝不可读、超大、格式错误、含未知字段、版本错误、工具未知、列表重叠或模式无效的策略。见 [05-deployment.zh.md](../05-deployment.zh.md)。

`/health` 暴露 `health.guardrails`，包含 `enabled`、`read_only`、`allow_tools`、`deny_tools`、`allowed_hosts`、`block_private_network`、`redact_secrets` 与 `content_boundary`；列表字段是计数，绝不是名称。REST `/api/v1/health` 返回同一对象。

## 已知限制

- 导航门禁不是网络沙箱。允许的页面加载后，页面脚本仍可请求被拒来源，子资源也不会被 `allowed_hosts` 过滤。
- 从不解析 DNS。通过模式的主机名仍可解析到私有地址，DNS 重绑定不会被检测。
- `browser_eval`、`page_html` 与 `browser_history` 仍可能暴露密钥；脱敏只覆盖上述 cookie 值，粘贴的 HTML 属性不会被清洗。
- JSON 快照不会被内容边界包裹；只有紧凑快照文本、`page_text` 的文本与 `page_html` 的 HTML 会被包裹。
- `browser_type` 的结果形状因通道而异：扩展对密码字段返回 `masked: true`，其他输入返回截断的 `value`；CDP 不返回 `value`，也不返回 `masked`。
- 1.6.0 QA 报告记录了一项针对上述 `browser_type` 按通道结果形状差异的 Low 发现，未记录 High 或 Medium 发现。
- REST 认证账号与刷新令牌保存在内存中；守护策略不增加持久身份。
- 分发后的重定向拒绝会在浏览器可能已跟随重定向之后报告 `POLICY_DENIED`。
- `details.policy` 会向直连 MCP 与 REST 客户端暴露本地策略路径；扩展界面会隐藏它。
- 不宣称任何 1.6.0 实机部署，NFR-3 仍未通过。QA PASS 在 HEAD `61ca85f` 的工作树上测得；发布由标签 `v1.6.0` 发布，产物是 CI 重建产物。独立的本地安装包 ZIP 已通过本地验收（84 项检查与观察、0 失败），但不是已发布产物。
