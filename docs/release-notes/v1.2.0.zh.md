# Corvus 1.2.0

发布日期：2026-11-15。

Corvus 是一个本地 Rust 守护进程加一个 Manifest V3 浏览器扩展，通过 stdio 或 streamable HTTP 把用户正在使用的浏览器提供给 MCP 客户端。1.2.0 是混合传输版本：MCP 工具面从 32 个增至 42 个，守护进程可选地通过回环浏览器级 CDP 直连驱动以远程调试启动的浏览器，扩展仍是零配置默认路径。

## 交付内容

- 原有 32 个 MCP 工具的参数与结果结构保持不变，另新增十个 CDP 与辅助工具。
- 浏览器级 CDP 直连客户端：单条长连接 WebSocket、展平的 Target 会话、1000 条事件环、250 毫秒至 10 秒退避重连、15 秒心跳，以及默认 10 秒、最大 60 秒的命令超时。
- 启动时与运行时均可选通道：`auto`、`cdp` 与 `extension`。`auto` 优先 CDP，仅在路由为 Unsupported 时回退；`cdp` 严格直连、绝不回退；`extension` 忽略 CDP。
- 扩展在回环端口 9222、9223、9333 上探测 CDP，并按同一浏览器家族选择端点；端点保存在 `corvus.cdpEndpoint`。
- `tools/list` 支持两级分类与默认简版 / 完整详情切换；`tool_help` 返回完整描述。
- 延续 1.1.0 的单根目录布局、Windows 安装器、Linux x86_64 安装包、Docker 镜像与 Kubernetes 清单；发布门禁现在断言 1.2.0 与 42 个工具。
- 扩展设置页保存守护进程地址与可选 CDP 端点。

## 工具面

新增的十个名称为 `cdp_status`、`cdp_targets`、`cdp_send`、`cdp_events`、`browser_channel`、`browser_console`、`browser_cookies`、`browser_dialog`、`browser_emulate` 与 `tool_help`。

## 通道矩阵

| 模式 | 传输 | 回退 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | CDP 已连接时优先，否则扩展 | 仅当 CDP 路由为 Unsupported | 未配置端点时保持扩展通道 |
| `cdp` | 仅浏览器级 CDP 直连 | 无 | 仅扩展工具会失败，不会静默换通道 |
| `extension` | 仅扩展 | 无 | 忽略已配置的 CDP 端点 |

用 `--channel`、`CORVUS_CHANNEL` 或 `browser_channel` 工具选择模式。`--cdp-endpoint` 接受 `/json/version` 返回的回环 `ws://` 或 `wss://` 浏览器地址；`--no-cdp` 移除 CDP 路径。扩展设置页接受 `auto` 或显式的 `http://127.0.0.1:<port>` 发现端点。

CDP 仅限宿主机回环且没有认证。浏览器级端点可控制该浏览器实例中的所有 profile；绝不要暴露 9222、9223 或 9333。启动参数、工具 schema、事件处理与故障排查见 [07-cdp.zh.md](../07-cdp.zh.md)。

## 安装

### Windows

发布 ZIP 包含 `install-windows.ps1`、`uninstall-windows.ps1` 与随包的 `nssm.exe`。在解压目录中打开管理员 PowerShell 并执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

默认根目录为 `%ProgramData%\Corvus`；加载 `%ProgramData%\Corvus\extension` 下的未打包扩展。旧的 `%USERPROFILE%\.corvus` 目录会迁移到新根目录下，除非设置 `-KeepLegacyData`。详见 [04-install.zh.md](../04-install.zh.md)。

### Linux x86_64

```bash
mkdir -p corvus-1.2.0-linux-x86_64
tar -xzf corvus-1.2.0-linux-x86_64.tar.gz -C corvus-1.2.0-linux-x86_64
cd corvus-1.2.0-linux-x86_64
sha256sum -c SHA256SUMS
sudo ./install-linux.sh
```

安装器需要 root 与运行中的 systemd。它创建 `corvus` 服务用户，安装到 `/opt/corvus`，写入并启动 unit，然后等待 `http://127.0.0.1:7331/health`。扩展位于 `/opt/corvus/extension`。详见 [05-deployment.zh.md](../05-deployment.zh.md)。

### Docker

```bash
docker volume create corvus-data
docker build -t corvus:1.2.0 .
docker run -d --name corvus \
  -p 127.0.0.1:7330:7330 -p 127.0.0.1:7331:7331 \
  -v corvus-data:/data corvus:1.2.0
curl -fsS http://127.0.0.1:7331/health
```

镜像以 UID/GID 10001 运行，`/data` 是其根目录，扩展位于 `/opt/corvus/extension`。镜像不含浏览器，也无法访问宿主机浏览器回环，因此请在容器内使用扩展通道或 `--no-cdp`。

### Kubernetes

```bash
docker build -t corvus:1.2.0 .
kind load docker-image corvus:1.2.0   # 或推送到你的镜像仓库
kubectl apply -k deploy/k8s
kubectl -n corvus port-forward svc/corvus 7330:7330 7331:7331
```

Service 刻意使用 ClusterIP。浏览器扩展无法直接访问它；请使用 port-forward 或运维方提供的带认证代理。Pod 默认无法访问 CDP。细节见 [deploy/k8s/README.md](../../deploy/k8s/README.md)。

## 验证

```bash
curl -fsS http://127.0.0.1:7331/health     # status ok，版本 1.2.0
curl -fsS http://127.0.0.1:7331/metrics   # Prometheus 文本
corvus doctor
```

MCP `tools/list` 返回恰好 42 个工具。不带参数调用 `browser_channel` 可读取当前模式、CDP 连接与扩展状态；`cdp_status` 返回端点、浏览器、协议版本、目标数量、重连次数与最后错误。预期使用 CDP 但未连接时，先检查启动端口与扩展探测状态，再考虑切换通道。

## 已知限制

- NFR-3 未通过。干净的 72 小时压测在客户要求下于约八小时后停止，1.2.0 不能宣称通过 72 小时压测。
- Firefox 仍不支持（NFR-6 偏差不变）。支持浏览器为 Edge、Chrome 与 Brave（Chromium 120+）。
- CDP 仅限回环且没有认证，浏览器级端点可控制该浏览器实例中的所有 profile。绝不要暴露 9222、9223 或 9333。
- 发布 Docker 镜像与 Kubernetes 清单不含浏览器，也无法访问宿主机浏览器回环。sidecar 浏览器不是开箱即用路径；请使用扩展通道或 `--no-cdp`。
- 强制 `cdp` 绝不回退，因此仅扩展工具需要扩展，共享工具在 CDP 路由不可用时可能失败。
- macOS 没有打包安装器；Linux 打包仅支持 x86_64。镜像未发布到镜像仓库，Kubernetes 清单只是发布门禁检查，并非托管部署。
- 本版本不宣称完成 1.2.0 的实际部署。用于打包的开发机继续运行原有的 1.0.0 服务。
- 扩展标签 id 与 CDP 目标 id 属于不同命名空间。v1.2.0 返回类型化 `BAD_ARGS` 提示，仅扩展工具可省略 `tab_id` 使用；完整桥接推迟到 1.3。
- 守护进程已连接时修改显式配置的扩展 CDP 端点，可能需要重启守护进程才能生效。自动发现的端点变化会重新轮询并自动重连（重连已验证）。

## 从 1.1.0 升级

录制 schema 仍为版本 1，1.1.0 的数据库可原地打开，无需迁移。

- Windows：用相同的 `-HomeDir` 运行 1.2.0 安装器。安装器刷新二进制与扩展，保留 `data/corvus.db`。
- Linux：用 1.2.0 归档替换已安装目录并重跑 `install-linux.sh`；保留 `<root>/data` 与 `<root>/config`。
- Docker：重建或拉取 1.2.0 镜像，保留命名卷 `/data`。Kubernetes：更新 deployment 中的镜像标签。
- 替换扩展文件后重新加载。原有守护进程地址设置保留；CDP 端点仍为可选。运行 `corvus doctor`、检查 `/health`，并调用 `tools/list` 确认 42 个工具。

另见[安装指南中的升级](../04-install.zh.md)与 [05-deployment.zh.md](../05-deployment.zh.md)。
