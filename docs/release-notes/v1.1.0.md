# Corvus 1.1.0

Released 2026-11-15.

Corvus is a local Rust daemon plus a Manifest V3 browser extension. It exposes the browser that the user already runs to MCP clients over stdio or streamable HTTP. 1.1.0 is a deployment release: the 32-tool surface is unchanged, and every backend file now lives under one root.

## What ships

- The same 32 MCP tools, per-tab scheduling and MCP request cancellation as 1.0.0.
- A single-root layout selected by `--home <DIR>` or `CORVUS_HOME`: `bin/`, `data/corvus.db`, `logs/`, `config/` and `extension/`.
- Daily rolling file logs at `logs/corvusd.log.YYYY-MM-DD` in UTC, with `--log-file` and `--no-log-file` overrides.
- A Windows service installer that defaults to `%ProgramData%\Corvus`.
- A Linux x86_64 tarball with a systemd unit, install and uninstall scripts, and `SHA256SUMS`.
- An amd64 Docker image and Kubernetes manifests that put the same root at `/data`.
- An extension options page for a custom `ws://` or `wss://` daemon URL.
- `corvus config --home <DIR>` pins stdio snippets to that root; HTTP snippets are unchanged.

## Install

### Windows

The release ZIP contains `install-windows.ps1` and `uninstall-windows.ps1` at its root. Open an elevated PowerShell in the extracted archive and run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

The default root is `%ProgramData%\Corvus`; load the unpacked extension from `%ProgramData%\Corvus\extension`. From a repository checkout, build the bundle with `bash scripts/package.sh` and run `.\scripts\install-windows.ps1` instead. The full procedure, including custom ports and uninstall, is in [04-install.md](../04-install.md).

### Linux x86_64

```bash
mkdir -p corvus-1.1.0-linux-x86_64
tar -xzf corvus-1.1.0-linux-x86_64.tar.gz -C corvus-1.1.0-linux-x86_64
cd corvus-1.1.0-linux-x86_64
sha256sum -c SHA256SUMS
sudo ./install-linux.sh
```

The installer needs root and a running systemd. It creates the `corvus` service user, installs under `/opt/corvus`, writes and starts the unit, and waits for `http://127.0.0.1:7331/health`. Load the extension from `/opt/corvus/extension`. Overrides and uninstall are in [05-deployment.md](../05-deployment.md).

### Docker

```bash
docker volume create corvus-data
docker build -t corvus:1.1.0 .
docker run -d --name corvus \
  -p 127.0.0.1:7330:7330 -p 127.0.0.1:7331:7331 \
  -v corvus-data:/data corvus:1.1.0
curl -fsS http://127.0.0.1:7331/health
```

The container runs as UID/GID 10001 with `/data` as its home. The image carries the unpacked extension at `/opt/corvus/extension`, while `/data` holds only runtime data; copy it out with `docker cp` or load the extension from the release ZIP on the host. Publish only to host loopback; the daemon has no authentication.

### Kubernetes

```bash
docker build -t corvus:1.1.0 .
kind load docker-image corvus:1.1.0   # or push to your registry
kubectl apply -k deploy/k8s
kubectl -n corvus rollout status deployment/corvus
kubectl -n corvus port-forward svc/corvus 7330:7330 7331:7331
```

The Service is a ClusterIP. A browser extension cannot reach it directly; use the port-forward, or an authenticated proxy that the operator provides. See [deploy/k8s/README.md](../../deploy/k8s/README.md).

## Client configuration

Generate the entry with the installed binary:

```bash
/opt/corvus/bin/corvus config --transport http
```

On Windows use `%ProgramData%\Corvus\bin\corvus.exe`. `--client` accepts `claude`, `cursor`, `dsh`, `cline` or `generic`. Add `--home <DIR>` to pin a stdio snippet to a specific root. For a stdio-only client, stop the service first; the service and the stdio bridge cannot share the default ports.

## Verify

```bash
curl -fsS http://127.0.0.1:7331/health
curl -fsS http://127.0.0.1:7331/metrics
corvus doctor
```

`/health` reports the version, bound addresses and the recording database path. `/metrics` returns Prometheus text. An MCP `tools/list` request returns 32 tools. `doctor` reports the database path, schema version, session and step counts, uptime and tool totals.

## Known limitations

- The clean NFR-3 72-hour soak started 2026-11-14T14:41:37Z and was stopped at the client's request after about eight hours (last checkpoint 8 at 2026-11-14T22:41:37Z). The planned 72-hour run will not be completed. NFR-3 is not passed in 1.1.0 and the release is not 72-hour soak certified.
- Firefox 121+ is unsupported. The NFR-6 deviation remains open with option A (keep Firefox outside the supported matrix) recommended.
- The daemon has no authentication. Ports 7330 and 7331 must stay on loopback; a remote `wss://` endpoint needs a trusted tunnel or an authenticating proxy.
- Linux packaging is x86_64 only. macOS has no packaged installer in this release and runs from source.
- The Docker image is not published to a registry, and Kubernetes manifests are release-gate CI checks rather than a hosted cluster.

## Upgrade from 1.0.0

The database schema is version 1, so a 1.0.0 database opens in place.

- Windows: run the 1.1.0 installer with the same `-HomeDir`. The default root is now `%ProgramData%\Corvus`; a legacy `%USERPROFILE%\.corvus` tree is moved to `<HomeDir>\migration\userprofile-corvus` unless `-KeepLegacyData` is set. Deprecated `-InstallDir`, `-DataDir` and `-ExtensionDir` values must resolve inside the home root.
- Linux: 1.0.0 had no package. Install the 1.1.0 archive and either start with `--home` pointing at the existing root or copy the old `corvus.db` (and its `-wal`/`-shm` files while stopped) into `<root>/data/`.
- Reload the extension after replacing its files, confirm the daemon URL on the options page when a custom URL is used, then run `corvus doctor` and check the reported version.

See [Upgrade in the install guide](../04-install.md) and [05-deployment.md](../05-deployment.md).
