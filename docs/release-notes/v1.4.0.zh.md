# Corvus 1.4.0

发布日期：2026-11-15。本说明描述 1.4.0 发布版本。v1.4.0 验收报告记录了 HEAD 65fbf52 上的 PASS；最终 CI 运行 43690906863 与 GitHub Release 445893367 见下表。

Corvus 是本地 Rust 守护进程加 Manifest V3 浏览器扩展。它把用户已经在用的浏览器，经 stdio 或 streamable HTTP 暴露给 MCP 客户端。1.4.0 是结构版本：后端改为端口与适配器结构，REST `/api/v1` 面与 MCP 并列，录制迁移到 SeaORM，扩展改为由 TypeScript 与 Vue 3 源码构建。MCP 工具面本身保持 43 个工具不变，紧凑单文本结果信封与 `browser_batch` 与 1.3.0 完全一致。

## 交付内容

- `corvus-domain` 承载纯领域模型，`corvus-application` 承载用例与 `BrowserRegistry`、`BrowserSession`、`StepRecorder`、`ToolCatalog` 四个端口。`corvus-cdp`、`corvus-transport`、`corvus-record`、`corvus-mcp` 与 `corvus-api` 是适配器；`corvusd` 负责装配。`corvus-runtime` 已删除。
- REST `/api/v1`：健康、浏览器、会话、工具与认证。OpenAPI JSON 位于 `/api-docs/openapi.json`，Swagger UI 位于 `/docs`。REST 与 MCP 共用同一套 43 工具目录与执行器。
- 可选的本地认证：Argon2id 口令、HS256 JWT、900 秒访问令牌与轮换的 30 天刷新令牌。回环地址上认证默认关闭，不存在默认账号；绑定非回环地址且未启用认证时，除非显式设置 `--allow-no-auth` / `CORVUS_ALLOW_NO_AUTH`，否则启动失败。
- SeaORM 与 `sea-orm-migration` 录制，`schema_version` 为 1。既有数据库无需数据迁移即可打开；迁移前写入 `VACUUM INTO` 备份，备份失败则中止启动。存储保持 WAL、单写入连接、5 秒 busy timeout、30 天保留与 262144 字节载荷截断。
- 扩展由 TypeScript 与 Vue 3 重写：弹窗与设置页使用 Vue 3、Pinia 与 Naive UI；Service Worker、内容脚本与 offscreen 文档使用无框架 TypeScript；类型化 RPC；三次 Vite 构建输出到 `extension/build/extension`；MV3 十项权限；21 个单元、契约与组件测试，外加隔离的 Playwright 套件。
- 1.1.0 引入的单根目录布局、Windows 安装器、Linux x86_64 包、Docker 镜像与 Kubernetes 清单继续提供，版本标注为 1.4.0。Docker 镜像入口会传入 `--allow-no-auth`；这是显式的不安全豁免，不是开箱即用的安全容器。

| 类别 | 工具数 |
| --- | --- |
| 页面 | 10 |
| 输入 | 7 |
| 标签页 | 4 |
| 网络 | 5 |
| 文件 | 3 |
| CDP | 5 |
| 会话 | 4 |
| 诊断 | 4 |
| 帮助 | 1 |
| **合计** | **43** |

1.4.0 验收实测简版列表正文 20,451 字节，完整详情 37,066 字节。1.4.0 不改变工具名、schema 或结果形状。通道可用性也不变：两个通道共享 25 个浏览器类工具，8 个仅 CDP，0 个仅扩展，10 个守护进程本地。

## 通道矩阵

| 模式 | 传输 | 回退 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | 已连接时用 CDP，否则用扩展 | 仅当 CDP 路由为 Unsupported | 扩展仍是零配置路径 |
| `cdp` | 仅浏览器级 CDP 直连 | 无 | 提供全部 33 个浏览器类工具 |
| `extension` | 仅扩展 | 无 | 提供 25 个浏览器类工具；8 个仅 CDP 工具返回类型化错误 |

可用 `--channel`、`CORVUS_CHANNEL` 或 `browser_channel` 工具选择模式。CDP 仍仅限宿主机回环且没有认证；见 [07-cdp.zh.md](../07-cdp.zh.md)。

## REST API 与认证

守护进程在 `/mcp` 所在同一 HTTP 端口提供：

| 方法 | 路径 |
| --- | --- |
| GET | `/api/v1/health` |
| GET | `/api/v1/browsers` |
| GET | `/api/v1/browsers/{id}` |
| GET | `/api/v1/sessions` |
| GET | `/api/v1/sessions/{id}` |
| GET | `/api/v1/sessions/{id}/steps` |
| GET | `/api/v1/tools` |
| POST | `/api/v1/tools/call` |
| POST | `/api/v1/auth/login` |
| POST | `/api/v1/auth/refresh` |
| POST | `/api/v1/auth/logout` |
| GET | `/api/v1/auth/me` |

认证由 `--auth off|local` / `CORVUS_AUTH` 控制。`local` 需要至少 32 字节的签名密钥，以及启动用户名与口令；没有默认凭据。访问令牌有效期 900 秒。刷新令牌有效期 30 天，以 Argon2id 散列保存并在使用时轮换。每个响应都带 `x-request-id`；路由器加入链路追踪、120 秒超时并返回 408、gzip 压缩，CORS 仅允许回环来源。

bearer 守卫只覆盖 `/api/v1`，其中 `/api/v1/health`、login 与 refresh 豁免。即使启用本地认证，`/mcp`、扩展 WebSocket、旧版 `/health`、`/metrics`、`/api-docs/openapi.json` 与 `/docs` 仍无认证。因此 REST 认证不会让非回环守护进程对远程安全。1.4.0 的账号与刷新令牌保存在内存中，重启后不保留。

## 持久化与升级

录制库保持 `schema_version` 1。1.3.0 数据库无需数据迁移即可打开，也仍可被 1.3.0 二进制读取。在既有文件上执行基线迁移前，守护进程先写入 `VACUUM INTO <db>.backup-<millis>.db`；备份失败则中止启动。单个录制任务消费写入队列，读取在专用录制线程执行；此前活动的会话标记为 `abandoned`，超过 30 天的会话被删除，参数与结果在 UTF-8 边界处截断到 262144 字节。

## 扩展构建

构建并从生成目录加载扩展：

```bash
pnpm --dir extension install
pnpm --dir extension build
```

加载 `extension/build/extension`。构建执行三次 Vite 过程，最后复制 manifest，校验十项权限与 module Service Worker，并拒绝 source map。弹窗与设置页是 Vue 3 应用；Service Worker、内容脚本与 offscreen 文档保持无框架 TypeScript。

## 安装

### Windows

发布 ZIP 包含 `install-windows.ps1`、`uninstall-windows.ps1` 与随包的 `nssm.exe`。解压后在提升权限的 PowerShell 中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

默认根目录为 `%ProgramData%\Corvus`；从 `%ProgramData%\Corvus\extension` 加载扩展。旧的 `%USERPROFILE%\.corvus` 目录会在未设置 `-KeepLegacyData` 时迁移到新根目录。见 [04-install.zh.md](../04-install.zh.md)。

### Linux x86_64

```bash
mkdir -p corvus-1.4.0-linux-x86_64
tar -xzf corvus-1.4.0-linux-x86_64.tar.gz -C corvus-1.4.0-linux-x86_64
cd corvus-1.4.0-linux-x86_64
sha256sum -c SHA256SUMS
sudo ./install-linux.sh
```

安装器需要 root 与运行中的 systemd。它创建 `corvus` 服务用户，安装到 `/opt/corvus`，启动 unit 并等待 `http://127.0.0.1:7331/health`。见 [05-deployment.zh.md](../05-deployment.zh.md)。

### Docker

```bash
docker volume create corvus-data
docker build -t corvus:1.4.0 .
docker run -d --name corvus \
  -p 127.0.0.1:7330:7330 -p 127.0.0.1:7331:7331 \
  -v corvus-data:/data corvus:1.4.0
curl -fsS http://127.0.0.1:7331/health
```

镜像以 UID/GID 10001 运行，`/data` 为根目录，扩展位于 `/opt/corvus/extension`。其入口传入 `--allow-no-auth`，因此容器明确没有认证，不是开箱即用的安全配置；只发布到宿主机回环。要启用 REST 认证，请用 `--env-file` 传入四个 `CORVUS_AUTH*` 变量。镜像不含浏览器，也无法访问宿主机浏览器回环。

### Kubernetes

`deploy/k8s/` 中的清单创建命名空间、PVC、守护进程 Deployment、ClusterIP Service 与 NetworkPolicy。仓库内的 Deployment 覆盖了镜像入口并传入 `--allow-no-auth`，因此 Pod 可以启动，但明确没有认证，不是开箱即用的安全配置。MCP、扩展 WebSocket、`/health`、`/metrics`、`/api-docs/openapi.json` 与 `/docs` 仍无认证。CDP 默认无法从 Pod 访问。见 [deploy/k8s/README.md](../../deploy/k8s/README.md)。

## 已知限制

- 1.4.0 的 REST 认证账号与刷新令牌保存在内存中，重启后重置。持久化认证存储属于后续工作。
- bearer 守卫只覆盖 `/api/v1`。即使启用本地认证，`/mcp`、扩展 WebSocket、旧版 `/health`、`/metrics`、`/api-docs/openapi.json` 与 `/docs` 仍无认证。任何非回环监听都应置于可信认证代理之后。
- 仓库内的 Kubernetes Deployment 覆盖了镜像入口并传入了 `--allow-no-auth`。Pod 可以启动，但部署明确没有认证，MCP 仍无认证；该豁免不保护 MCP。
- NFR-3 未通过。计划中的 72 小时压测在约八小时停止后仍未完成；1.4.0 不能宣称通过压测。
- Firefox 仍不支持（NFR-6 偏差不变）。支持浏览器为 Edge、Chrome 与 Brave（Chromium 120+）。
- CDP 仅限回环且没有认证；发布 Docker 镜像与 Kubernetes 清单不含浏览器，也无法访问宿主机浏览器回环。
- 强制 `cdp` 不回退；macOS 没有打包安装器；Linux 打包仅支持 x86_64。
- 首次打包检查时，浏览器启动曾短暂通过 CDP 附加到用户 9222 端口上的 Edge 实例，未发生 MCP/REST 调用或页面导航；随后停止并改为隔离重跑。
- 扩展标签 id 与 CDP 目标 id 仍属于不同命名空间；跨通道引用返回类型化 `BAD_ARGS`。
- 不宣称已有 1.4.0 实机部署。开发机仍运行既有的 1.0.0 服务。

## 从 1.3.0 升级

`schema_version` 仍为 1，因此 1.3.0 数据库可原地打开。在既有文件上执行基线迁移前，守护进程先写 `VACUUM INTO` 备份；备份失败则中止启动。

- Windows：使用相同的 `-HomeDir` 运行 1.4.0 安装器。它会刷新二进制与扩展，并保留 `data/corvus.db`。
- Linux：用 1.4.0 归档替换已安装目录并重跑 `install-linux.sh`；保留 `<root>/data` 与 `<root>/config`。
- Docker：重建或拉取 1.4.0 镜像并保留命名 `/data` 卷。Kubernetes：更新镜像 tag；仓库内的 Deployment 已传入 `--allow-no-auth`，可让 Pod 启动，但部署明确没有认证。
- 从源码重建扩展或替换打包目录，然后重新加载。既有守护进程 URL 与 CDP 端点设置会保留。运行 `corvus doctor`，检查 `/health` 与 `/api/v1/health`，并调用 `tools/list` 确认 43 个工具。

见[安装指南中的升级部分](../04-install.zh.md)与 [05-deployment.zh.md](../05-deployment.zh.md)。
