## 工作树中的内容

本工作为 `page_snapshot` 增加浏览器感知与差异能力，并把扩展界面国际化。它不新增 MCP 工具：目录仍为 43 个工具、九个类别。

## 快照感知 v2

`page_snapshot` 现在遍历开放 shadow root 与同源子 frame。顶层文档的 frame 路径为空；子 frame 按文档顺序为 `f0`、`f0.0`、`f1` 等。子 frame 内的紧凑行追加 `frame="<path>"`，JSON 节点仅在路径非空时带 `frame`。存在子 frame 的页面添加 `frames: {total, included, skipped: [{frame, url, reason}]}`；`reason` 为 `cross_origin`、`unavailable` 或 `geometry_unavailable`，跨源 frame 被跳过而不是静默丢弃。`max_nodes` 是全部已包含文档共用的一个预算，`include_bbox` 的包围盒相对顶层视口，`viewport_only` 与 `include_bbox` 的其他行为不变。

## 紧凑差异

`diff` 是布尔输入，默认 false，仅适用于紧凑输出；`format: "json"` 与 `diff` 同时使用返回类型化 `BAD_ARGS`。守护进程应用层按浏览器、会话与标签页为键的 64 项 LRU 计算一次差异，因此扩展、CDP 直连与 `browser_batch` 路径共用同一语法。`diff: false` 的紧凑请求刷新基线；差异请求从不刷新，JSON 也不触碰基线。同一 URL 存在基线时，结果添加 `diff: {baseline: true, unchanged, changed, added, removed}`，当前行以两个空格（未变）、`+ `（新增）或 `~ `（变化）标记；基线中无匹配的行按旧顺序以 `- ` 追加。没有基线或 URL 变化时，报告 `{baseline: false, 0, 0, 0, 0}`，文本不带标记。见 [09-tools.zh.md](../09-tools.zh.md)。

## 扩展国际化

Vue 界面使用 vue-i18n 11.4.20，英文与简体中文各 64 个键的目录位于 `extension/src/ui/shared/i18n/`。语言检测读取 `chrome.i18n.getUILanguage()` 与 `navigator.language`：`zh*` 选择 `zh-CN`，其余选择英文。显式选择保存在 `corvus.locale`，无需刷新即可响应式切换，`document.documentElement.lang` 跟随当前语言。MV3 manifest 声明 `default_locale: en`；`_locales/en` 与 `_locales/zh_CN` 为扩展名称、描述与 action 标题镜像目录。构建现在输出 14 个文件，其中包括两份目录；十项权限、25 个处理器与 `all_frames: false` 保持不变。

## 工具面

MCP 目录与 1.4.0 相同：43 个工具、九个类别，成功的 `tools/call` 返回一个紧凑 JSON 文本块，不含 `structuredContent`，`browser_batch` 最多 20 个允许的步骤。通道可用性不变：扩展通道 25 个浏览器类工具，强制 CDP 为 33 个。

## 通道矩阵

| 模式 | 传输 | 回退 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | 已连接时用 CDP，否则用扩展 | 仅当 CDP 路由为 Unsupported | 扩展仍是零配置路径 |
| `cdp` | 仅浏览器级 CDP 直连 | 无 | 覆盖全部 33 个浏览器类工具 |
| `extension` | 仅扩展 | 无 | 覆盖 25 个浏览器类工具 |

与 1.4.0 一致；CDP 仍仅限宿主机回环且没有认证。见 [07-cdp.zh.md](../07-cdp.zh.md)。

## 架构

十个 crate 不变：`corvus-domain`、`corvus-application`、`corvus-api`、`corvus-proto`、`corvus-mcp`、`corvus-transport`、`corvus-record`、`corvus-cdp`、`corvusd` 与 `corvus`。`crates/corvus-application/src/snapshot_diff.rs` 持有基线缓存，`crates/corvus-application/src/router.rs:483` 的 `Router::finish_page_snapshot` 对扩展路径、`crates/corvusd/src/lib.rs` 的 CDP 直连路径以及每个 `browser_batch` 步骤只应用一次。`crates/corvus-cdp/src/tools.rs` 遍历 frame 树；`extension/src/content/runtime.ts` 在扩展通道执行同样的遍历。没有新增 crate，也没有录制 schema 变更。

## 扩展构建

```bash
pnpm --dir extension install
pnpm --dir extension build
```

加载 `extension/build/extension`。构建执行三次 Vite，最后复制 manifest，并校验必需文件、1.5.0 版本检查、十项权限、ESM Service Worker 与无 source map。manifest、构建检查与一致性快照均指向 1.5.0。

## 已知限制

- NFR-3 仍未通过；72 小时浸泡在约八小时后停止。
- 不宣称任何 1.5.0 实机部署，也不为本工作宣称任何 Docker 或 Kubernetes 运行时证据。
- 工作树版本已为 1.5.0，QA 与 Windows 安装包验收是在脏工作树上测得的；尚不存在标签或 CI 运行。本地安装包 ZIP 不是已发布产物，发布前仍需完成 Pending 的 CI 与已发布产物门禁。
- 快照差异仅用于紧凑输出；`format: "json"` 与 `diff` 同时使用返回类型化 `BAD_ARGS`。
- 跨源 frame 被跳过且永不读取，因此其内容不会出现在快照中。
- 打包验收时，第一次 harness 调用曾短暂把浏览器级 CDP 连接到 9222 端口上的日常 Edge。该连接没有发送任何 MCP/REST 工具调用或页面导航；测试服务随即停止，测试端点固定到已关闭的 9666 端口，记录的浏览器套件只使用隔离端口 17364/17365、9555 与 17400。
