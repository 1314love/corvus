# Corvus 1.3.0

发布日期：2026-11-15。

Corvus 由本地 Rust 守护进程与 Manifest V3 浏览器扩展组成，通过 stdio 或可流式 HTTP 把用户正在使用的浏览器暴露给 MCP 客户端。1.3.0 是 token 效率版本：MCP 工具面从 42 个增至 43 个，`page_snapshot` 在两个通道上都默认返回紧凑文本，工具发现默认精简，强制 CDP 现在覆盖全部浏览器类工具。原有 32 个结果形状保持不变。

## 本版交付

- `browser_batch`：一次调用最多顺序执行 20 个允许列表内的浏览器步骤，`stop_on_error` 默认 true，返回逐步结果数组。该工具由守护进程本地处理，不发送到浏览器通道。
- 扩展与 CDP 两个通道都支持紧凑 `page_snapshot`：默认 `format: "compact"`，`format: "json"` 返回原有节点对象形状，支持 `viewport_only`、`include_bbox` 与 `max_nodes`。
- 精简 `tools/list`：默认简版，移除标题与 schema 属性描述；`detail: "full"` 恢复它们。`tool_help` 返回单个完整条目或类别索引。
- CDP 完整对等：全部 33 个浏览器类工具。此前仅扩展的八个工具在强制 `cdp` 下可用，CDP 快照提供 `@c<backendNodeId>` 引用。
- 九个工具类别、共 43 个工具，每个定义带 `_meta["corvus.category"]`。
- 日志遵循统一的文档化事件结构，启动只输出一条 `corvusd listening` 事件；见 [08-logging.md](../08-logging.zh.md)。
- 成功的 `tools/call` 只返回一个紧凑 JSON 文本块，不返回 `structuredContent`；客户端解析 `content[0].text`。
- 1.1.0 引入的单根目录布局、Windows 安装器、Linux x86_64 安装包、Docker 镜像与 Kubernetes 清单继续提供。发布断言改为 1.3.0 / 43 个工具。

## 通道矩阵

| 模式 | 传输 | 回退 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | 已连接时走 CDP，否则走扩展 | 仅当 CDP 路由为 Unsupported | 扩展仍是零配置路径 |
| `cdp` | 仅直接浏览器级 CDP | 无 | 覆盖全部 33 个浏览器类工具，包括此前仅扩展的八个 |
| `extension` | 仅扩展 | 无 | 覆盖 25 个浏览器类工具；8 个仅 CDP 工具返回类型化错误 |

用 `--channel`、`CORVUS_CHANNEL` 或 `browser_channel` 工具选择模式。`--cdp-endpoint` 接收 `/json/version` 返回的完整回环 `ws://` 或 `wss://` 浏览器地址；`--no-cdp` 关闭 CDP 路径。扩展设置页接受 `auto` 或显式 `http://127.0.0.1:<port>` 发现端点。

CDP 仅限宿主机回环且没有认证。浏览器级端点可控制该浏览器实例中的所有 profile；绝不要暴露 9222、9223 或 9333。启动参数、快照引用、工具结构与排错见 [07-cdp.zh.md](../07-cdp.zh.md)。

## 安装

### Windows

发布 ZIP 包含 `install-windows.ps1`、`uninstall-windows.ps1` 与随包提供的 `nssm.exe`。在解压目录中以管理员 PowerShell 运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

默认根目录为 `%ProgramData%\Corvus`；从 `%ProgramData%\Corvus\extension` 加载解压后的扩展。旧的 `%USERPROFILE%\.corvus` 目录树会迁移到新根目录下，除非设置 `-KeepLegacyData`。详见 [04-install.zh.md](../04-install.zh.md)。

### Linux x86_64

```bash
mkdir -p corvus-1.3.0-linux-x86_64
tar -xzf corvus-1.3.0-linux-x86_64.tar.gz -C corvus-1.3.0-linux-x86_64
cd corvus-1.3.0-linux-x86_64
sha256sum -c SHA256SUMS
sudo ./install-linux.sh
```

安装器需要 root 与运行中的 systemd。它创建 `corvus` 服务用户，安装到 `/opt/corvus`，写入并启动 unit，然后等待 `http://127.0.0.1:7331/health`。从 `/opt/corvus/extension` 加载扩展。详见 [05-deployment.zh.md](../05-deployment.zh.md)。

### Docker

```bash
docker volume create corvus-data
docker build -t corvus:1.3.0 .
docker run -d --name corvus \
  -p 127.0.0.1:7330:7330 -p 127.0.0.1:7331:7331 \
  -v corvus-data:/data corvus:1.3.0
curl -fsS http://127.0.0.1:7331/health
```

镜像以 UID/GID 10001 运行，家目录为 `/data`，扩展位于 `/opt/corvus/extension`。镜像不含浏览器，也无法访问宿主机浏览器回环，因此容器内请使用扩展通道或 `--no-cdp`。

### Kubernetes

```bash
docker build -t corvus:1.3.0 .
kind load docker-image corvus:1.3.0   # 或推送到你的镜像仓库
kubectl apply -k deploy/k8s
kubectl -n corvus port-forward svc/corvus 7330:7330 7331:7331
```

Service 为 ClusterIP。浏览器扩展无法直接访问，请使用端口转发或运维提供的带认证代理。Pod 默认无法访问宿主机 CDP。详见 [deploy/k8s/README.md](../../deploy/k8s/README.md)。

## 验证

```bash
curl -fsS http://127.0.0.1:7331/health     # status ok, version 1.3.0
curl -fsS http://127.0.0.1:7331/metrics   # Prometheus 文本
corvus doctor
```

MCP `tools/list` 恰好返回 43 个工具。无参数调用 `browser_channel` 可读取当前模式、CDP 连接与扩展状态；`cdp_status` 返回端点、浏览器、协议版本、目标数、重连次数与最近错误。紧凑快照返回一个文本块，客户端必须 `JSON.parse` `content[0].text`。

## 已知限制

- NFR-3 未通过。干净的 72 小时压测在客户要求下于约八小时后停止，1.3.0 不能宣称通过 72 小时压测。
- Firefox 仍不支持（NFR-6 偏差不变）。支持浏览器为 Edge、Chrome 与 Brave（Chromium 120+）。
- CDP 仅限回环且没有认证；浏览器级端点可控制该浏览器实例中的所有 profile。绝不要暴露 9222、9223 或 9333。
- 发布 Docker 镜像与 Kubernetes 清单不含浏览器，也无法访问宿主机浏览器回环。sidecar 浏览器不是开箱即用路径；请使用扩展通道或 `--no-cdp`。
- 强制 `cdp` 不会回退。端点不可用时浏览器类调用直接失败，不会改走扩展。
- macOS 没有打包安装器；Linux 打包仅支持 x86_64。镜像不发布到镜像仓库，Kubernetes 清单是发布门禁检查而不是托管部署。
- 扩展标签 id 与 CDP 目标 id 仍属于不同命名空间。`@eN` 与 `@c<backendNodeId>` 引用按通道区分，跨通道使用返回类型化 `BAD_ARGS`；完整桥接延后。
- 守护进程已连接时修改显式配置的扩展 CDP 端点，可能需要重启守护进程才能生效。自动发现的端点每 500 毫秒重新轮询并自动重连。
- 已披露一次历史性的预冻结只读 `GET /json/version`，访问对象为 9222 端口上的 Edge。最终验收矩阵改用 9555 端口上的隔离无头 Edge，未对用户日常 Edge profile 执行导航、挂载或交互。
- M2b 扩展矩阵针对已提交夹具使用了一个临时适配驱动；该适配仅用于测试，未改动产品代码。
- 不宣称已有 1.3.0 实机部署。用于打包的开发机继续运行原有的 1.0.0 服务。

## 从 1.2.0 升级

录制 schema 仍为版本 1，1.2.0 数据库可原地打开，无需迁移。

- Windows：用相同 `-HomeDir` 运行 1.3.0 安装器。安装器刷新二进制与扩展，保留 `data/corvus.db`。
- Linux：用 1.3.0 归档替换已安装目录并重新运行 `install-linux.sh`；保留 `<root>/data` 与 `<root>/config`。
- Docker：重建或拉取 1.3.0 镜像，保留命名 `/data` 卷。Kubernetes：更新 Deployment 的镜像 tag。
- 替换扩展文件后重新加载扩展。原有的守护进程 URL 与 CDP 端点设置会保留。运行 `corvus doctor`、检查 `/health`，并调用 `tools/list` 确认 43 个工具。

升级步骤另见 [安装指南中的升级章节](../04-install.zh.md) 与 [05-deployment.zh.md](../05-deployment.zh.md)。
