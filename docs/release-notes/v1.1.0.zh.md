# Corvus 1.1.0

发布于 2026-11-15。

Corvus 是一个本地 Rust 守护进程加一个 Manifest V3 浏览器扩展，通过 stdio 或 streamable HTTP 把用户正在使用的浏览器提供给 MCP 客户端。1.1.0 是部署版本：32 个工具面保持不变，所有后端文件归入单一根目录。

## 交付内容

- 与 1.0.0 相同的 32 个 MCP 工具、按标签调度与 MCP 请求取消。
- 由 `--home <DIR>` 或 `CORVUS_HOME` 选择的单根目录：`bin/`、`data/corvus.db`、`logs/`、`config/` 与 `extension/`。
- 每日滚动文件日志，位于 `logs/corvusd.log.YYYY-MM-DD`（UTC），可用 `--log-file` 与 `--no-log-file` 覆盖。
- Windows 服务安装器，默认根目录为 `%ProgramData%\Corvus`。
- Linux x86_64 tar 包，包含 systemd unit、安装与卸载脚本以及 `SHA256SUMS`。
- amd64 Docker 镜像与 Kubernetes 清单，同样把根目录放在 `/data`。
- 扩展设置页，可保存自定义 `ws://` 或 `wss://` 守护进程地址。
- `corvus config --home <DIR>` 让 stdio 片段固定使用该根目录；HTTP 片段不变。

## 安装

### Windows

发布 ZIP 的根目录包含 `install-windows.ps1` 与 `uninstall-windows.ps1`。在解压目录中打开管理员 PowerShell 并执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1
```

默认根目录为 `%ProgramData%\Corvus`；加载 `%ProgramData%\Corvus\extension` 下的未打包扩展。在仓库检出中，请先用 `bash scripts/package.sh` 构建发布包，再执行 `.\scripts\install-windows.ps1`。自定义端口与卸载见 [04-install.zh.md](../04-install.zh.md)。

### Linux x86_64

```bash
mkdir -p corvus-1.1.0-linux-x86_64
tar -xzf corvus-1.1.0-linux-x86_64.tar.gz -C corvus-1.1.0-linux-x86_64
cd corvus-1.1.0-linux-x86_64
sha256sum -c SHA256SUMS
sudo ./install-linux.sh
```

安装器需要 root 与运行中的 systemd。它创建 `corvus` 服务用户，安装到 `/opt/corvus`，写入并启动 unit，然后等待 `http://127.0.0.1:7331/health`。扩展位于 `/opt/corvus/extension`。覆盖参数与卸载见 [05-deployment.zh.md](../05-deployment.zh.md)。

### Docker

```bash
docker volume create corvus-data
docker build -t corvus:1.1.0 .
docker run -d --name corvus \
  -p 127.0.0.1:7330:7330 -p 127.0.0.1:7331:7331 \
  -v corvus-data:/data corvus:1.1.0
curl -fsS http://127.0.0.1:7331/health
```

容器以 UID/GID 10001 运行，`/data` 是它的根目录。镜像把未打包扩展放在 `/opt/corvus/extension`，`/data` 只保存运行数据；请用 `docker cp` 复制出来，或在宿主机上使用发布 ZIP 中的扩展。只发布到宿主机回环地址；守护进程没有认证层。

### Kubernetes

```bash
docker build -t corvus:1.1.0 .
kind load docker-image corvus:1.1.0   # 或推送到你的镜像仓库
kubectl apply -k deploy/k8s
kubectl -n corvus rollout status deployment/corvus
kubectl -n corvus port-forward svc/corvus 7330:7330 7331:7331
```

Service 刻意使用 ClusterIP。浏览器扩展无法直接访问它；请使用 port-forward，或运维方提供的带认证代理。细节见 [deploy/k8s/README.md](../../deploy/k8s/README.md)。

## 客户端配置

用已安装的二进制生成条目：

```bash
/opt/corvus/bin/corvus config --transport http
```

Windows 使用 `%ProgramData%\Corvus\bin\corvus.exe`。`--client` 接受 `claude`、`cursor`、`dsh`、`cline` 或 `generic`。添加 `--home <DIR>` 可把 stdio 片段固定到指定根目录。仅使用 stdio 的客户端需要先停止服务；服务与 stdio 桥不能共用默认端口。

## 验证

```bash
curl -fsS http://127.0.0.1:7331/health
curl -fsS http://127.0.0.1:7331/metrics
corvus doctor
```

`/health` 报告版本、监听地址与录制数据库路径。`/metrics` 返回 Prometheus 文本。MCP `tools/list` 返回 32 个工具。`doctor` 报告数据库路径、schema 版本、会话与步骤数量、运行时长与工具总量。

## 已知限制

- 干净的 NFR-3 72 小时压测于 2026-11-14T14:41:37Z 启动，在客户要求下于约八小时后停止（最后检查点 8：2026-11-14T22:41:37Z）。计划中的 72 小时运行不会完成。1.1.0 未通过 NFR-3，也不能宣称通过 72 小时压测。
- 暂不支持 Firefox 121+。NFR-6 偏差仍未关闭，建议采用方案 A（把 Firefox 保持在支持矩阵之外）。
- 守护进程没有认证层。7330 与 7331 必须保持在回环地址；远程 `wss://` 端点需要可信隧道或带认证代理。
- Linux 打包仅支持 x86_64。macOS 在本版本没有打包安装器，只能从源码运行。
- Docker 镜像未发布到镜像仓库；Kubernetes 清单只属于发布门禁的 CI 检查，没有在托管集群上验证。

## 从 1.0.0 升级

数据库 schema 为版本 1，1.0.0 的数据库可以原地打开。

- Windows：用相同的 `-HomeDir` 运行 1.1.0 安装器。默认根目录现在是 `%ProgramData%\Corvus`；旧的 `%USERPROFILE%\.corvus` 目录会迁移到 `<HomeDir>\migration\userprofile-corvus`，除非设置 `-KeepLegacyData`。已弃用的 `-InstallDir`、`-DataDir` 与 `-ExtensionDir` 必须解析到根目录内部。
- Linux：1.0.0 没有安装包。安装 1.1.0 压缩包后，用 `--home` 指向旧根目录启动，或在停止守护进程后把旧的 `corvus.db`（以及 `-wal`/`-shm` 文件）复制到 `<root>/data/`。
- 替换扩展文件后重新加载；使用自定义地址时在设置页确认守护进程 URL；然后运行 `corvus doctor` 检查版本。

另见[安装指南中的升级](../04-install.zh.md)与 [05-deployment.zh.md](../05-deployment.zh.md)。
